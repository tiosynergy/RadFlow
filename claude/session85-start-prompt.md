## 5. Правила работы — не переоткрывать

**Безопасность и данные** — как в с80–с83: секреты и ПИИ никуда; прод-данные только по явному
списку id и с до-образами; разбирая таблицы с ПИИ — агрегатами; живые замеры UI на проде — только
чтением DOM, без скриншотов; дев и прод — ОДНА база; `npm audit fix --force` запрещён; пароли не
спрашивать и не вводить; протоколы безопасности — проверка собственной конфигурации, без эксплойтов.
**События Auth — в потоке логов, не в таблице:** `query_logs` (ClickHouse-таблица `logs`,
`source = 'auth_audit_logs'` — события, `'auth_logs'` — запросы GoTrue с `path`/`status`/`error`;
ПДн — `actor_username`/`traits.user_email` — не выбирать). **Сигнатуру ожидаемой ветки называть ДО
живой проверки** (урок с83: «успешно проверено» дважды оказалось другой веткой).

**Миграции и проверки** — «сухой» прогон без маркера отката = накат; «успех» — не доказательство,
проверяй запросом; накатил — сразу смёржил (красное окно); окно `apply → db:gate` не через 03:50
UTC; всё про RLS/гранты/DEFINER/триггеры/авторизацию — **два независимых раунда ревью разными
линзами** (для серверной авторизации в с83 помогла третья — «атакующий»), выводы субагентов
проверять лично; CSS-правка контейнера — мерить в безголовом Chromium на реальном DOM (jsdom-снимки
компонента) «до/после», харнес вне репо, пины — на правила. Утверждение о дефолте колонки — запросом
к каталогу; UI-список = CHECK только через тест, читающий миграцию.
