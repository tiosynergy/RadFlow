## ЗАДАЧА СЕСІЇ

### 1. ⚠️ ЖИВА ПЕРЕВІРКА «КРАПОК» — найголовніше

**Фічу ще не бачив жоден користувач.** Непрямі ознаки роботи є (8 погашених
позначок), але це не заміна проходу очима. Два браузерні контексти
(адмін + направник; **паролі вводить власник**):

- направник міняє склад досліджень свого направлення → у адміна крапка на
  «Дошка черги» в сайдбарі, на картці, біля блоку послуг **і на дні в
  міні-календарі**;
- адмін РОЗГОРТАЄ картку → крапки гаснуть на ВСІХ його вкладках (realtime);
  **згорнута картка крапку НЕ гасить** — перевірити окремо;
- наступна зміна направника → нова крапка (прочитане не перевикористовується);
- адмін переносить направлення на іншу дату → крапка ПЕРЕЇЖДЖАЄ на новий день,
  на старому не лишається;
- адмін скасовує запис → крапка в «Скасовані + Неявка», гасне при розкритті
  панелі;
- відкликання доступу направника → крапка на «Мої центри» у ВІДКЛИКАНОГО;
- перевірити журнал: подвійних подій немає; консоль: помилок
  `mark_changes_seen` немає.

Якщо тригери завадять щоденному потоку — стоп-кран без міграції:
`update public.change_marker_settings set enabled = false;`

**Хвости, які так і не перевірялись живцем** (тягнуться з с25/с26):
`/journal` під реальним адміном (резолв імен, «Показати ще», фільтр за ID),
`/search` за ID і під ролями radiologist / referrer / ceo, тости 0129
(«У кабінеті вже є пацієнт» / «…перекриє наступний запис кабінету»).

## Правила, які не можна порушувати

Повний список — `AGENTS.md`. Найважливіше з першої хвилини:

- **Міграції застосовує власник вручну**; номер — наступний за максимальним
  ЗАСТОСОВАНИМ по прод-БД (`0133` зараз → нова `0134`). Порядок: СПЕРШУ
  міграція в БД, ПОТІМ клієнт. **Комітить власник.**
- **⚠️ Dry-run реальними байтами файла:** `pglast` (справжній парсер Postgres)
  + репетиція через `execute_sql` («міграція + смоук + `raise exception`»);
  ПІСЛЯ накату — смоук ще раз, уже проти застосованої схеми.
- **Будь-яка зміна RLS / RPC / тригерів / серверних роутів → ревʼю субагентом,
  і ДРУГИЙ раунд по самих фіксах.** с27: 14 + 9 знахідок, причому фікс
  першого раунду («очевидний» `pg_trigger_depth`) сам виявився High у другому —
  він зробив би скасування кейса невидимим.
- **Журнал і крапки — ДВА РІЗНІ шари.** `important_events` (0128) — fail-OPEN,
  прикладна емісія, «одна дія — одна подія». `user_change_markers` (0131–0133) —
  fail-CLOSED тригери, адресність по кожній зачепленій сутності. Не
  «уніфікувати»: обґрунтування — шапка 0131.
- **Одиниця позначки = одиниця згортання.** Усе, чого немає в ключі
  `(recipient, entity_type, entity_id, field_scope)`, ON CONFLICT мусить
  оновлювати явно; порядок емісій у тригері значущий. Масова операція
  зобовʼязана згортатись (каталог — агрегат по КАБІНЕТУ).
- **Позначка, яку неможливо погасити, — це дефект.** Перевіряй: чи є екран,
  де ця сутність видима, і чи є там ack. Ретенція непрочитані НЕ чистить.
- **⚠️ Переносиш інваріант з UI у БД — спершу випиши правило, яке вже працює
  на клієнті, і доведи еквівалентність** (урок с26).
- **Інваріант БД без дати + UI зі зрізом по даті** = або вічне блокування
  (с24), або неможливість показати (с27). Дата має жити В РЯДКУ.
- **PII не тягни в сесію агента** (агрегати, не вибірки рядків); у `details`
  позначок — лише контрольовані ключі, список заборонених один на проєкт
  (`name` теж заборонений — для назв послуг ключ `label`).
- **Два запити в одному `reload` — це гонка.** Лічильник поколінь перед кожним
  `setState`, і в дошках, і в ХУКАХ, і в модульному store.
- **`opacity` НЕ носій стану; статус — глифом І кольором; чіпав кольори —
  `npm run audit:contrast`** (він у `npm test`). У с27 саме він знайшов
  крапку 1.49:1 на синій комірці «сьогодні».
- **`tsc`/`eslint` НЕ парсять CSS** → чіпав `.css`, роби `npm run build`.
- **Нова модалка → додай її в гард гарячих клавіш `anyModalOpen`.**
- **⚠️ РЕВʼЮ НЕ ЗАМІНЮЄ ЖИВОЇ ПЕРЕВІРКИ.**

- **⚠️ Шелла на пристрої НЕМАЄ** (`device_bash` = «Workspace unavailable»).
  Доставка: `device_request_folder_access("D:\RadFlowDev")` один раз за сесію →

  `expectedMtimeMs`. Git робить власник — готуй команди.
- **⚠️ `device_stage_files` може віддати ЗАСТАРІЛИЙ вміст при СВІЖИХ
  метаданих** (урок с27). Виглядає як «власник відкотив усі правки»: diff
  чистий, grep нічого не знаходить. Сторож: звір `bytes` із відповіді
  інструмента з реальним розміром локальної копії (`wc -c`); `device_list_dir` —
  незалежне джерело правди. **Перш ніж оголошувати розбіжність — прожени цю
  перевірку.**
- **⚠️ `prosrc like '%щось%'` матчить і КОМЕНТАРІ всередині функції** (той самий
  урок с27, друга хибна тривога). Для перевірки «чи справді викликається» —
  регексп по конструкції, а не по імені.
- **Тулчейн — на клоні з GitHub:**
  `git clone --depth 1 -b dev https://github.com/tiosynergy/RadFlow.git /tmp/radflow`
  → `npm ci` → `typecheck && lint && test && build`.
- **`execute_sql`:** при ПОМИЛЦІ відкочує все (дешевий dry-run); при УСПІХУ
  комітить → зонд мусить закінчуватись `raise exception`. NOTICE назовні НЕ
  віддає — з смоука видно лише фінальний виняток. Імперсонація:
  `set_config('request.jwt.claims', json_build_object('sub',uid,'role','authenticated')::text, true)`;
  `set_config('role','authenticated')` назад не перемикається — став усередині
  sub-блоку, перехоплений виняток відкотить роль сам.
- **Смоук-фікстури бʼються об живі тригери:** модальність (0088), `rooms.active`
  (0123), графік `ROOM_CLOSED`/`OFF_SCHEDULE` (0084), минуле (0063), сітка 5 хв
  (0125), один `in_progress` на кабінет (0018). Кабінет обирай data-driven по
  ВСІХ клініках, день — перебором `+28..+34`.
  Смоук крапок додатково вимагає: 2 клініки з адмінами, реєстратора в першій,
  радіолога з кабінетом, направника, ВІДКРИТИЙ кейс БЕЗ done-кроків.
- **У хмарному контейнері є Chromium + Playwright** (`/opt/pw-browsers/chromium`)
  і `pip install pglast`.
- **Міграцій у БД не відстежує жодна таблиця** — номер звіряй по факту
  наявності обʼєктів (аудит H-2).
- **dev і prod — ОДИН проєкт Supabase**: фіксуй вихідний стан, явні id,
  прибирай за собою.
- **Мердж-цикл:** `compare/dev...main` → PR → «Merge» тисне ВЛАСНИК →
  `git fetch` + `git merge --ff-only origin/main` + `git push origin dev`.
- **Живий UI** — Claude-in-Chrome проти `npm run dev` на пристрої. Вузькі
  екрани — через iframe; вкладка зазвичай `hidden` (`AudioContext` suspended).
- **Планувальник** — лише `mcp__claude-code-remote__*`, не локальний cron.
