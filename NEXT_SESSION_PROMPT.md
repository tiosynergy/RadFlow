## ⚠️ РЕЖИМ РОБОТИ: НАПРЯМУ В ПАПЦІ ПРОЄКТУ

**Працюй НАПРЯМУ в `D:\RadFlowDev`** через міст пристрою: читаєш файли
`device_stage_files`, доставляєш `SendUserFile` → `device_commit_files`.
Правки мають опинятись на диску, а не лише в чаті.

Правила мосту, перевірені кров'ю в с34–с35:

- **Перед перезаписом ІСНУЮЧОГО файла** — застейдь його і зроби diff проти
  своєї версії. Розбіжності мають бути ЛИШЕ твої. Так у с35 виявилось, що
  `supabase/types.ts` на диску не містив блоку, який я вважав доставленим.
- **Після доставки** — застейдь назад і звір md5. Без цього «доставив» —
  це припущення, а не факт.
- **Міст періодично відвалюється** («device not connected»). Тоді: файли в
  чат через `SendUserFile`, і при реконнекті `device_commit_files` по тому
  самому `file_uuid` — він переживає розрив (перевірено двічі).
- **Шелла на пристрої немає** (`device_bash` недоступний). `git` запускає
  власник. Але `.git/HEAD`, `.git/logs/HEAD`, `.git/FETCH_HEAD` можна
  СТЕЙДЖИТИ і читати — саме так у с35 з'ясувалось, що коміт лежить у `dev`,
  а не в `main`.
- **Видаляти файли заборонено** — `mv` у `_to_delete/`. Виняток: git-tracked
  файл прибирає власник через `git rm`.

Клон для тулчейна — у контейнері: `/tmp/rfmain`
(`https://github.com/tiosynergy/RadFlow.git`, **репозиторій ПУБЛІЧНИЙ**).
`git fetch origin main && git reset --hard origin/main` швидше за перестворення.
Клон single-branch: `git fetch origin dev` треба звати явно.

3. `.gitignore` ловить дампи за іменем — **тільки `.txt`**, ширше не робити

Якщо токен знову опиниться в переписці — **відкликай негайно**, до
розбирань: `key:revoke --id <uuid>`. Перевипуск нічого не коштує.

## Правила, які не можна порушувати

- **Міграції накатує ВЛАСНИК** у SQL Editor. Ти готуєш файл + смоук + секцію
  відкату, робиш dry-run реальними байтами і наскрізний прогін
  (міграція+смоук в одній транзакції під `rollback`), два ревʼю і раунд
  фіксів — і віддаєш. Номер — із `select max(name) from migration_ledger`.
- **Смоук: асерти лише `is distinct from`.** `<>` з NULL дає NULL, `if NULL`
  = false → провалений крок проходить МОВЧКИ.
- **Фікстури смоука мусять проходити форматні констрейнти** (sha256-хеші,
  префікси, enum) — інакше прогін падає на фікстурі й не перевіряє нічого.
- **`to_regclass` окремим statement-ом**, ніколи не голий `::regclass` у тій
  самій умові: plpgsql планує statement цілком (42P01/42703 до short-circuit).
- **Новий тип `important_events` = чотири правки**: union у
  `lib/importantEvents.ts`, case у `lib/journalText.ts`, група в
  `EVENT_TYPE_GROUPS`, `DETAIL_KEYS` у `app/api/journal/route.ts`.
- **Валідація «без керуючих символів» — по СИРОМУ рядку**, до trim.
- **Порядок уведення фічі з міграцією+кодом**: накат → деплой → увімкнення;
  вікно «старий код + нова БД» проєктувати порожнім.
- dev і prod — **одна БД**. `npm audit fix --force` не можна. PII в `details`
  заборонено. Планувальник — тільки `mcp__claude-code-remote__*`.
  Node-скрипти: без main-guard, типи через JSDoc.
- Мерж і пуш робить власник через GitHub web; ти готуєш текст коміту й PR.
