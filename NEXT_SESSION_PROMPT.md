## Правила работы (не нарушать)

- **Миграции применяет владелец вручную** через Supabase SQL Editor. Ты пишешь файл и даёшь
  порядок накатки. Номер — следующий за максимальным в `supabase/migrations/`. Идемпотентность обязательна.
- **Мультитенантность (clinic_id / RLS) критична.** Любое изменение RLS, политик, RPC или
  триггеров → **обязательно ревью субагентом**. Оно ловило блокер практически каждый раз.
- **Статусы/обзвон/перенос пишутся ТОЛЬКО через RPC** (`queue_set_status_rpc`, `queue_set_call_rpc`,
  `queue_confirm_calls_rpc`, `queue_reschedule_rpc`). Прямой `.from("queue_entries").update({status})`
  теперь падает с 42501 — так и задумано.
- **Каждая НОВАЯ колонка `queue_entries`** требует `grant update (col) on public.queue_entries
  to authenticated;` — иначе UI молча получит 42501 (следствие 0070).
- **Время:** «сейчас» — только через `wallNow(clinics.timezone)` / `wallDayKey(tz)`.
  `new Date()` в TS и `now()` в SQL с настенным временем **несравнимы** (отсюда были три бага).
- **Ошибка загрузки ≠ «пусто»:** в лоадерах проверяй `error`, поднимай флаг, не затирай старые
  данные (канон — `lib/slotBusy.ts`).
- `npm run typecheck && npm run lint && npm test` перед каждым коммитом. Коммитит владелец.
- Bash-песочница агента отдаёт **устаревшие копии файлов** — доверяй только Read/Edit/Write.
- Браузерные проверки — Claude-in-Chrome против `npm run dev` (localhost:3000).
  Пароли вводит владелец, не агент. Dev и prod смотрят в **один** проект Supabase — тестовые
  действия меняют реальные данные, убирай за собой.

## Ловушки этого проекта (стоили прод-блокеров)

- `create or replace` функции — **всегда диффай с последней действующей редакцией**
  (0060 так «потеряла» буфер и `not_held`).
- Колоночный `REVOKE` при табличном `GRANT UPDATE` — **no-op**. Supabase раздаёт табличный грант:
  сначала `revoke update on table`, потом `grant update (cols)`.
- SRF (`returns setof`) нельзя в `WHERE`: пиши `in (select fn())`, а не `= any(fn())`.
- `SECURITY DEFINER` **не применяет RLS** — вся авторизация должна быть в теле функции.
- Политики RLS — `to authenticated` и с `(select fn())`: иначе anon ловит 42501, а STABLE-функция
  вызывается на каждую строку.
- Любой новый запрет статусного перехода **синхронно убирай из UI**, иначе остаётся мёртвая кнопка
  (так вышло с «✓ Виконано» в панели опоздания).
- Ранний выход в триггере формулируй через то, что защищаешь («занятость не выросла»), а не через
  удобный признак («слот не менялся») — иначе молча отключишь инвариант в соседнем случае (0068).
