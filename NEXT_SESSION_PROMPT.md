## ЩО РОБИТИ ДАЛІ (за пріоритетом)

### 0. Хвости, які закриваються за хвилини

- Довести до `main` пакет звуку перевищення, якщо він ще в `dev`.
- Закрити тестовий запис «test sound 1» (тривалість 55 хв, зсунутий старт).
- Коли тестовий сів стане не потрібен — прогнати
  `supabase/maintenance/2026-07-30_cleanup_seed_s19.sql` з `v_dry := false`.
  ⚠️ Скрипт відмовиться працювати, якщо хоч один засіяний рядок видалити руками
  (звірка md5) — тоді потрібен свіжий знімок ID.

### 1. `--blue` під білим текстом = 3.65:1 — потрібне РІШЕННЯ ВЛАСНИКА

Це всі `.btn-primary`, активні пілюлі, активні чипи днів — **27 вузлів лише на
`/setup`**. WCAG 1.4.3 AA вимагає 4.5:1. Технічно правка на один токен, але це
зміна брендового акценту, тому **спитай власника, а не вирішуй сам**. Заміряні
варіанти:

| варіант | білий на ньому | коментар |
|---|---|---|
| `#0a84ff` (зараз) | 3.65 | не проходить |
| `#0b74e0` | 4.58 | мінімально прохідний, найближчий до поточного |
| `#0d6ecf` | 5.06 | із запасом |
| `#1268c2` | 5.55 | помітно темніший |

Там же: `--blue` як колір ТЕКСТУ = 3.82:1. Освітлений `--blue-text: #4da3ff`
(5.31) уже в палітрі, але в проєкті **~80 хардкодів того ж значення** — їх варто
звести до токена одним механічним проходом (візуально no-op).

Покажи «до/після» на живому dev, перш ніж міняти.

### 2. Ротація `SUPABASE_SERVICE_ROLE_KEY` (P0, відкладається з сесії 13)

Ключ ротує власник у Supabase. Твоя частина: чек-лист усіх місць використання
(`lib/supabase/admin.ts` + усі роути, що його беруть), порядок заміни без простою
і перевірка після. Заодно перевір `/api/auth/login-available`: при відмові БД він
відповідає `available: null`, а не «вільний» — переконайся, що клієнт трактує це
fail-closed.

### 3. Залишок контрасту (WCAG)

- Інпути `.equip-block.equip-off .equip-info > input` лишились на `opacity: .55`.
  Там `color` НЕ еквівалент — своя заливка і placeholder; потрібна жива перевірка.
- Дрібні провали палітри: `.sb-badge` 3.41, `.sb-cab-count` 3.94, порожній стан
  `.ei` 1.86.
- Метод заміру: аудитор у браузері, який множить весь ланцюг `opacity` і окремо
  бере фон УСЕРЕДИНІ групи та підкладку ПІД нею. Формула «колір на фоні» тут бреше.

### 4. Компонентних тестів немає взагалі (jsdom не налаштований)

Найболючіше це в `components/ImportPriceModal.tsx` (XHR, abort, машина станів
`pick / uploading / parsing / preview / applying`), а тепер ще й у
`useQueueSounds` / `SoundToggle` і у формах запису з фільтром контрасту: чиста
логіка покрита, компоненти — ні. Якщо берешся, це окрема інфраструктурна задача
(jsdom + `@testing-library/react`), а не «додати пару тестів».

### 5. Залишок UX-аудиту: МОДАЛКИ на 320px

Перевірялись лише екрани, що відкриваються прямо з маршруту. Не перевірені: запис,
перенос, кейс, поломка, імпорт прайсу. Прийом — iframe (див. `AGENTS.md`).

### 6. Відкладено власником

- **Канал сповіщення для outbox** — до хостингу і реального SMTP.
- **Доля публічності репозиторію** — зараз публічний, рішення відкладено.
- **Видалити недосяжну гілку `kind: "image"` з n8n-воркфлоу** — потребує Publish
  власником; без цього нічого не ламається, гілка просто мертва.
- **Доля колонок `services.contrast_allowed` / `contrast_price`** — після с20 вони
  ні на що не впливають (пишуться з назви). Дропати — окремим рішенням.

### 7. Інше з беклогу

Автономний режим (8 питань §12 плану); зміна логіна співробітника адміном;
апгрейд залежностей (**`npm audit fix --force` НЕ МОЖНА** — пропонує next@9).

**Carryover власника:** місячний spending limit в OpenAI. ⚠️ З 2026 «Budget limit»

## Правила, які не можна порушувати

Повний список — в `AGENTS.md`. Найважливіше з першої хвилини:

- **Міграції застосовує власник вручну** через Supabase SQL Editor. Номер —
  наступний за максимальним **ЗАСТОСОВАНИМ** (по прод-БД!). Прод на `0127` →
  наступна `0128`. Ідемпотентність обов'язкова. **Комітить власник.**
- **Порядок викатки: СПЕРШУ міграція в БД, ПОТІМ клієнт.**
- **Смоук НЕ кладуть у тіло міграції** — раннер виконує файл у транзакції, і
  `raise exception 'SMOKE_OK'` відкотить власний DDL. Смоуки — в `supabase/smoke/`.
- **Будь-яка зміна RLS / політик / RPC / тригерів / серверних роутів → ревʼю
  субагентом.** Окупається щоразу: с19 — 3 High, с20 — 5 High, с21 — 1 High.
  **І другий раунд — по САМИХ фіксах**: у с19 він дав ще 3 Medium, у с20 — ще 3 High.
- **Міняєш правило — шукай смоуки І ТЕСТИ, що стверджували СТАРЕ.**
- **Видалення даних прода — лише за явним списком ID зі свіжого знімка**, зі
  звіркою md5, dry-run через `raise exception` і перевіркою, що before-образи
  лягли в `audit_log`.
- **Паролі й ключі вводить власник.** Налаштування безпеки міняє власник.
- **`tsc` і `eslint` НЕ парсять CSS** — зламаний CSS ловить лише `npm run build`.
- **Заміряй, а не дивись.** Двічі статична перевірка пропускала те, що знайшов браузер.

## Середовище: що працює і що ні

- **⚠️ Шелла на пристрої НЕМАЄ.** Desktop Commander і `device_bash` віддають
  «Workspace unavailable». Живі `device_stage_files` і `device_commit_files`
  (шлях Windows-абсолютний). Усі git-команди й розпакування робить власник —
  готуй йому список команд, а не виконуй сам.
- **Тулчейн — на клоні з GitHub:**
  `git clone --depth 1 -b dev https://github.com/tiosynergy/RadFlow.git /tmp/radflow` →
  `npm ci` → `typecheck && lint && test && build`. Репозиторій публічний.
  Це ж — спосіб перевірити, що власник запушив саме те дерево, яке перевіряли.
- **Доставка:** одним тарболом у `D:\RadFlowDev\_sNN.tar.gz`; **окремі 1–5 файлів
  клади напряму по їхніх шляхах** — dev-сервер підхопить сам (найкращий цикл під
  час живої перевірки). ⚠️ Тарболи не в `.gitignore` — нагадуй видалити до
  `git add -A`. ⚠️ Якщо після пакування правив файл — ПЕРЕПАКУЙ тарбол, інакше
  розпакування відкотить правку (спіткнулись у с21).
- **Живий UI** — Claude-in-Chrome проти `npm run dev` на пристрої. Вузькі екрани —
  iframe; `requestAnimationFrame` у фоновій вкладці не викликається.
- **⚠️ Вкладка, якою керує Claude-in-Chrome, зазвичай `hidden`** — у ній не грає
  звук (політика браузера + власне правило «прихована вкладка мовчить») і
  `AudioContext` лишається `suspended`. Для перевірки звуку або проси власника
  тримати ЙОГО вкладку на передньому плані, або підміняй у сторінці
  `document.visibilityState` і геттер `state` у `BaseAudioContext.prototype` —
  тоді осцилятори створюються і їх видно лічильником (звуку не чути, але ланцюг
  перевіряється end-to-end).
- **Звук перевіряти патчем `OscillatorNode.prototype.start`** — пише кожен
  реальний пуск тону з частотою і типом хвилі: видно І факт звуку, І який саме
  профіль, І скільки разів.
- **⚠️ Звук перевищення НЕ перевіряють продовженням дослідження**: кнопка «+5 хв»
  збільшує `duration_min`, поріг їде вперед і перевищення скасовується.
- **dev і prod — ОДИН проєкт Supabase.** Міняти прод-дані для перевірки можна, але
  фіксуй вихідний стан, використовуй явні id і прибирай за собою.
- **Планувальник** — лише `mcp__claude-code-remote__*`, не локальний cron.
- Решта пасток — в `AGENTS.md` і в `claude/radflow-handoff.md`.
