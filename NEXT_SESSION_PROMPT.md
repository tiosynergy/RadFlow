## Стенд для живої перевірки (відкриття с31 — ЗАПАМʼЯТАЙ)

**Браузер власника бачить його `localhost` — контейнер ні.** Власник
піднімає `npm run dev` на своїй машині, розширення Claude-in-Chrome працює
в ЙОГО браузері → можна перевіряти БУДЬ-ЯКУ гілку без деплою. Перед
висновками ЗАВЖДИ звіряй `location.origin` і маркери в бандлі.

Методики (детально в `claude/session31-live-verification.md`):
- затримка мережі: патч `window.fetch` по `supabase.co/rest` (знімати після!);
- обрив realtime: `WebSocket.prototype.send` throw (реакція — до 60 с,
  heartbeat); «мертвий сокет на старті» — ТІЛЬКИ фізичне вимкнення Wi-Fi
  (DevTools Request blocking WebSocket НЕ перехоплює!);
- пробник сокета — ЛИШЕ зі СПРАВЖНІМ anon key (з `apikey=test` сервер сам
  дає onerror, це НЕ блокування — у с31 це ледь не стало фальшивим дефектом);
- замір UI не раніше 3 с (ретраї); тост soft-undo живе 6 с; «елемент зник» —
  тільки з контрольним заміром часу життя;
- рекордер кадрів `setInterval(150ms)` у `window.__frames` — для переходів;
- кліки — через DOM `.click()` по звіреному елементу (координати брешуть);
- після `location.reload()` — повторний `tabs_context_mcp`;
- два браузери розрізняй по deviceId (імена міняються між перепідключеннями).

## Правила, які не можна порушувати

Повний список — `AGENTS.md`. Найгостріше з с31:

- **Міграції застосовує власник вручну; комітить власник.** Спершу міграція
  в БД, потім клієнт. Номер — наступний за максимальним ЗАСТОСОВАНИМ (0135).
- **⚠️ Dry-run реальними байтами файла** (`pglast` + репетиція через
  `execute_sql` з `raise exception`); ПІСЛЯ накату — смоук проти
  застосованої схеми.
- **Зміни RLS/RPC/тригерів/серверних роутів → ревʼю субагентом ×2, і другий
  раунд по самих фіксах.** У с31 КОЖЕН раунд по КОЖНОМУ пакету знаходив
  MAJOR у самих фіксах (5 разів поспіль!). Це не формальність.
- **⚠️ Ревʼю не заміняє живої перевірки** — дефект «правка ПІБ рве
  направника» знайшов ВЛАСНИК живцем, жодне ревʼю його не бачило.
- **⚠️ Імена — НЕ ключі.** FK ніколи не резолвиться по відображуваному
  рядку. Селекти — на ключах. Порівняння імен — тільки нормалізовано
  (zName/zOptName на вході, norm на читанні легасі).
- **⚠️ zOptName НЕ для patch-обʼєктів** (undefined → null затре колонку);
  у патчах — union із .optional().
- **⚠️ CAS-конфлікт — P0001, НЕ 40001** (40001 ретраїться клієнтом вічно);
  мітка CAS — рядком end-to-end; NULL = «рядка не було», не «пропустити».
- **⚠️ `for update` під RLS МОВЧКИ ховає рядок від ролі без права запису** —
  явний гард ролі ДО блокуючого читання.
- **⚠️ Після конфлікту оновлювати знімок БЕЗ ремоунту стану не можна** —
  «узаконює» затирання. Ремоунт — тільки зі свіжими даними.
- **Ack-механіка**: точка ack = виклик `useAckWhenVisible`, не свій useEffect.
- **PII не тягни в сесію**; у `details` позначок — контрольовані ключі.
- **dev і prod — ОДНА БД.** Міняєш прод-дані — фіксуй вихідний стан, явні
  id, прибирай за собою. Перед масовим UPDATE — перевір тригери таблиці
  (guard-и і маркер-спам).
- **`npm audit fix --force` НЕ МОЖНА.**
- Планувальник — тільки `mcp__claude-code-remote__*`, НЕ локальний cron.
