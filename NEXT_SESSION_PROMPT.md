## ЗАДАЧА СЕСІЇ

### 1. ⚠️ Накат `0134` і ЖИВА ПЕРЕВІРКА — головне

**Порядок виконання жорсткий:**

1. **СПЕРШУ міграція в БД** (власник вручну, Supabase SQL Editor), **ПОТІМ
   деплой коду**. Код шле `actor_hint` у девʼяти місцях; без колонки PostgREST
   віддає PGRST204, і кожне запрошення направника / запит доступу / approve /
   decline / revoke падає з 400. Відкат — строго навпаки.
2. **ПІСЛЯ накату** прогнати `supabase/smoke/user_change_markers_smoke.sql`
   ЦІЛКОМ (блоки A–P) проти вже застосованої схеми. Це окрема перевірка від
   репетиції: репетиція перевіряла визначення всередині транзакції.
3. **Жива перевірка двома акаунтами** (два браузерні контексти, паролі вводить
   власник). Що саме дивитись:
   - адмін відкликає доступ направнику → **адмін НЕ отримує крапку про власну
     дію**, `actor_role` позначки = `admin` (а не `system`), направник крапку
     ОТРИМУЄ;
   - направник подає запит на доступ → дзеркально: у нього крапки немає, у
     адміна є;
   - адмін запрошує направника (`/referrers`) → те саме;
   - CEO: непрочитаних більше не зʼявляється взагалі;
   - **лист очікування і портал направника** — після переведення на
     `useAckWhenVisible` перевір ОБИДВА боки заморозки: позначка, що прилетіла
     при вже розгорнутому рядку, НЕ має гаснути сама; і навпаки — розгортання
     рядка мусить гасити те, що там було.

### 2. Хвости с28 (клієнтські, дешеві, не робились у с29)

- **Панель «Скасовані + Неявка» у адміна лежить у `.rpanel`**, яку ховає
  `@media (max-width: 1240px)` — на ноутбуці адмін не може погасити крапку
  скасування. У радіолога це вже виправлено переносом в основну колонку;
  адмінська потребує рішення по верстці (перенести вниз списку / зробити
  акордеон під контентом).
- Крапки `rooms` / `schedule` / `staff` у навігації майстра **свідомо не
  ввімкнені**: джерел у 0132 немає, а зʼявляться — крапка загориться без
  жодного ack. Додаєш поверхню — додай і точку підтвердження.
- `CompletionModal` не має пропа `busy` (кнопка активна весь час запиту) —
  у радіолога прикрито гардом у `finishComplete`, у `QueueBoard` гарда немає.

### 3. jsdom-тести — найдорожча прогалина (аудит L-2)

Компонентних тестів у проєкті НЕМА взагалі, і після с29 привід став ще
сильнішим: ack-механіка тепер тримається на заморозці знімка в `ref` **і** на
модульному backoff-і з таймером. Обидва регресять невидимо. Потрібні тести з
deferred-промісами і фейковими таймерами: розгортання картки; позначка, що
прилетіла ПРИ відкритому блоці (не має гаснути); помилка завантаження; зміна
користувача; перезаморозка по `refreezeKey`; **сходинки backoff-у** (успіх
сусіднього хука НЕ скидає паузу; серія згасає за часом; стеля 60 с досяжна).

## Правила, які не можна порушувати

Повний список — `AGENTS.md`. Найважливіше з першої хвилини:

- **Міграції застосовує власник вручну**; номер — наступний за максимальним
  ЗАСТОСОВАНИМ по прод-БД. Порядок: СПЕРШУ міграція в БД, ПОТІМ клієнт.
  **Комітить власник.**
- **⚠️ Схема і код зчеплені жорстко.** 0134 додала колонку, яку код згадує в
  девʼяти місцях: невідповідність у будь-який бік = 400 на всіх операціях із
  доступами. Додаєш колонку, яку пише клієнт, — пропиши порядок викоту в шапці
  міграції і в `ROLLBACK.md`.
- **⚠️ Dry-run реальними байтами файла:** `pglast` + репетиція через
  `execute_sql` («міграція + смоук + `raise exception`»); ПІСЛЯ накату — смоук
  ще раз, уже проти застосованої схеми.
- **Будь-яка зміна RLS / RPC / тригерів / серверних роутів → ревʼю субагентом,
  і ДРУГИЙ раунд по самих фіксах.** У с29 другий раунд знайшов блокер, СТВОРЕНИЙ
  фіксом першого раунду (захист для позначки, яку взагалі неможливо погасити).
- **⚠️ РЕВʼЮ НЕ ЗАМІНЮЄ ЖИВОЇ ПЕРЕВІРКИ — доведено с28.** Вісім знахідок із
  девʼяти були невидимі в коді.
- **⚠️ Коментар у коді — не доказ.** Інваріант, на який спираєшся, перевіряй сам.
  У с29 шапка міграції двічі містила твердження про UI, які ревʼю спростувало
  читанням коду.
- **Ack-механіка небезпечна СИМЕТРИЧНО**: погасити зайве = зникле сповіщення,
  не погасити = вічна крапка. Кожен фікс одного класу перевіряй на появу
  іншого — у с29 так вийшло ДВІЧІ поспіль.
- **Точка ack = виклик `useAckWhenVisible`, а не свій `useEffect`.** Власний
  ефект по `unreadIx` гасить ЖИВИЙ індекс: ні заморозки знімка, ні ретрая.
- **Один дефект живе в кількох ролях і на кількох поверхнях.** Знайшов одну
  негасиму крапку — перевір УСІХ отримувачів із матриці і ВСІ місця ack.
- **Позначка неіснуючому отримувачу — теж негасима.** Гілка, що підставляє
  сирий uuid, мусить звірятися з `profiles`.
- **Актор для service-role роутів — канал у рядку**, бо `set_config` із роуту
  не переживає межу транзакції PostgREST. Підказку ОБНУЛЯТИ одразу.
- **Журнал і крапки — ДВА РІЗНІ шари.** `important_events` (0128) — fail-OPEN,
  прикладна емісія. `user_change_markers` (0131–0134) — fail-CLOSED тригери.
  Не «уніфікувати»: обґрунтування — шапка 0131.
- **Одиниця позначки = одиниця згортання.** Усе, чого немає в ключі
  `(recipient, entity_type, entity_id, field_scope)`, ON CONFLICT мусить
  оновлювати явно; порядок емісій у тригері значущий.
- **Рубильник мусить рятувати ВІД УСІХ тригерів фічі.** Обчислення, здатне
  кинути виняток, не можна ставити в DECLARE — воно виконається до перевірки
  `change_markers_enabled()`, і вимикач не спрацює.
- **Дані поза робочим зрізом — ОКРЕМО від `entries`** (на них зав'язані звук,
  таймери кабінетів і лічильники дня).
- **PII не тягни в сесію агента**; у `details` позначок — лише контрольовані
  ключі (`name` заборонений, для назв послуг — `label`).
- **Два запити в одному `reload` — це гонка.** Лічильник поколінь перед кожним
  `setState` — і в дошках, і в хуках, і в модульному store, **і в ack**.
- **`opacity` НЕ носій стану; статус — глифом І кольором; чіпав кольори —
  `npm run audit:contrast`** (він у `npm test`).
- **`tsc`/`eslint` НЕ парсять CSS** → чіпав `.css`, роби `npm run build`.
- **Нова модалка → додай її в гард гарячих клавіш `anyModalOpen`** (у
  `RadiologistBoard` такого гарда немає взагалі — там не потрібно).

  метаданих** (урок с27). Сторож: звір `bytes` із відповіді інструмента з

- **⚠️ `prosrc like '%щось%'` матчить і КОМЕНТАРІ всередині функції.**
- **Тулчейн — на клоні з GitHub:**
  `git clone --depth 1 -b dev https://github.com/tiosynergy/RadFlow.git /tmp/radflow`
  → `npm ci` → `typecheck && lint && test && build`.

  комітить → зонд мусить закінчуватись `raise exception`. NOTICE назовні НЕ

  `set_config('request.jwt.claims', json_build_object('sub',uid,'role','authenticated')::text, true)`;

  sub-блоку.
- **⚠️ Репетиція міграції — це ОДНА транзакція.** Знімай `begin;`/`commit;` з
  тіла міграції, а відкат забезпечує фінальний `raise exception` смоука.
- **Смоук-фікстури бʼються об живі тригери:** модальність (0088), `rooms.active`
  (0123), графік `ROOM_CLOSED`/`OFF_SCHEDULE` (0084), минуле (0063), сітка 5 хв

- **У хмарному контейнері є Chromium + Playwright** (`/opt/pw-browsers/chromium`)
  і `pip install pglast`.
- **Міграцій у БД не відстежує жодна таблиця** — номер звіряй по факту
  наявності обʼєктів (аудит H-2).
- **dev і prod — ОДИН проєкт Supabase**: фіксуй вихідний стан, явні id,
  прибирай за собою.
- **Мердж-цикл:** `compare/dev...main` → PR → «Merge» тисне ВЛАСНИК →

  ⚠️ Вкладка Claude-in-Chrome зазвичай `hidden` (`AudioContext` suspended);
