## ЩО РОБИТИ ДАЛІ (за пріоритетом)

### 0. Викатка пакета с22 (перше!)

1. Власник розпаковує `_s22_search.tar.gz` у `D:\RadFlowDev`, **видаляє тарбол**,
   комітить у `dev`.
2. Склонуй `dev` з GitHub і прожени тулчейн — звір, що дерево збіглося.
3. **Жива перевірка на dev** (Claude-in-Chrome + власник):
   - `/search` під кожною роллю: область, фільтри, «Показати ще», стани;
   - швидкий пошук на дошках: часткове прізвище, середина номера, очищення;
   - deep-links: відкриття запису з результату на всіх дошках;
   - фільтри пошуку на вузькому екрані (iframe 320px).
4. Мердж у `main` після зеленої перевірки.

### 1. `--blue` під білим текстом = 3.65:1 — усе ще чекає РІШЕННЯ ВЛАСНИКА

WCAG 1.4.3 AA вимагає 4.5:1; це всі `.btn-primary`, активні пілюлі, чипи днів
(27 вузлів лише на `/setup`). Варіанти заміряні: `#0b74e0` (4.58) мінімально,
`#0d6ecf` (5.06) із запасом, `#1268c2` (5.55) темніший. Там же: ~80 хардкодів
`#4da3ff` звести до токена `--blue-text`. Покажи «до/після» на живому dev.

### 2. Ротація `SUPABASE_SERVICE_ROLE_KEY` (P0, тягнеться з с13)

Ключ ротує власник; твоя частина — чек-лист місць використання, порядок заміни
без простою, перевірка `/api/auth/login-available` (fail-closed при `null`).

### 3. Хвости даних прода

- Закрити «test sound 1» (досі відкритий).
- Коли сів не потрібен — `supabase/maintenance/2026-07-30_cleanup_seed_s19.sql`
  з `v_dry := false` (69 рядків на місці). ⚠️ md5-звірка відмовить, якщо хоч
  один засіяний рядок видалили руками — тоді свіжий знімок ID.

### 4. Залишок WCAG

Інпути `.equip-off .equip-info > input` на `opacity: .55`; `.sb-badge` 3.41,
`.sb-cab-count` 3.94, порожній стан `.ei` 1.86. Заміряти живим аудитором
(формула «колір на фоні» в групах прозорості бреше).

### 5. Компонентних тестів немає (jsdom не налаштований)

Тепер боляче ще й у `SearchScreen` (гонки запитів, chips, стани) — плюс старі
кандидати `ImportPriceModal`, `useQueueSounds`/`SoundToggle`, форми запису з
фільтром контрасту. Окрема інфраструктурна задача (jsdom + @testing-library).

### 6. Пошук — наступні ітерації (за потребою)

- WaitlistBoard досі на старому серверному ilike (середина номера не шукається);

- при зростанні історії — міграція `0128`: trigram + generated digits

## Правила, які не можна порушувати

Повний список — в `AGENTS.md`. Найважливіше з першої хвилини:

- **Міграції застосовує власник вручну**; номер — наступний за максимальним
  ЗАСТОСОВАНИМ по прод-БД (зараз `0127` → наступна `0128`). Смоук НЕ в тілі
  міграції — в `supabase/smoke/`. Ідемпотентність обовʼязкова. **Комітить власник.**
- **Порядок викатки: СПЕРШУ міграція в БД, ПОТІМ клієнт.**
- **Будь-яка зміна RLS / RPC / тригерів / серверних роутів → ревʼю субагентом,
  і другий раунд — по САМИХ фіксах.** с22 знову окупилось: 1 High + 6 Medium +
  5 Low у два раунди.
- **Область пошуку обчислює сервер із сесії** — клієнтські clinicIds/roomIds
  можуть тільки ЗВУЗИТИ її; значення в PostgREST `.or()` — тільки зі стислим
  алфавітом. **Радіолог по RLS бачить усю клініку — сервер зобовʼязаний звузити
  до призначених кабінетів.**
- **PII (ПІБ/телефон/рядок пошуку) не потрапляє в URL, storage, console,
  телеметрію.** У deep-links — лише uuid і дата.
- **Пошукові інпути НЕ канонізують ввід** (урок с22): матчинг цифровий
  (`lib/searchText.ts`), `formatPhoneSearch` лишився тільки у WaitlistBoard (свідомо).
- **Міняєш правило — шукай смоуки І ТЕСТИ, що стверджували СТАРЕ.**
- **Видалення даних прода — лише за явним списком ID** зі свіжого знімка, md5,
  dry-run через `raise exception`, звірка before-образів у `audit_log`.
- **`tsc`/`eslint` НЕ парсять CSS** — чіпав `.css` → `npm run build` обовʼязковий.
- **Заміряй, а не дивись.** І **звіряй байти через `od -c`/`repr()`** при
  автозаміні — у с22 знову спіткнулись об `\x01`-розділювач (утретє!).

## Середовище: що працює і що ні

- **⚠️ Шелла на пристрої НЕМАЄ.** Desktop Commander і `device_bash` віддають
  «Workspace unavailable». Живі `device_stage_files` і `device_commit_files`
  (шляхи Windows-абсолютні). Git і розпакування робить власник — готуй команди.
- **Тулчейн — на клоні з GitHub:**
  `git clone --depth 1 -b dev https://github.com/tiosynergy/RadFlow.git /tmp/radflow`
  → `npm ci` → `typecheck && lint && test && build`. Репозиторій публічний.
  Це ж — спосіб перевірити, що власник запушив саме перевірене дерево.
- **Доставка:** одним тарболом у `D:\RadFlowDev\_sNN.tar.gz`; окремі 1–5 файлів —
  напряму по шляхах (dev-сервер підхопить сам). ⚠️ Тарболи не в `.gitignore` —
  нагадуй видалити до `git add -A`. ⚠️ Правив файл після пакування — ПЕРЕПАКУЙ.
- **Живий UI** — Claude-in-Chrome проти `npm run dev` на пристрої. Вузькі екрани —
  iframe; `requestAnimationFrame` у фоновій вкладці не викликається.
- **⚠️ Вкладка Claude-in-Chrome зазвичай `hidden`**, `AudioContext` — `suspended`:
  для звуку — підміна `visibilityState`/`state` геттерами; факт звуку — патчем
  `OscillatorNode.prototype.start`. Перевищення НЕ перевіряти продовженням
  дослідження («+5 хв» зсуває поріг) — рухати `in_progress_at` назад.
- **dev і prod — ОДИН проєкт Supabase**: фіксуй вихідний стан, явні id, прибирай
  за собою.
- **Планувальник** — лише `mcp__claude-code-remote__*`, не локальний cron.
- Решта пасток — в `AGENTS.md` і в `claude/radflow-handoff.md`.
