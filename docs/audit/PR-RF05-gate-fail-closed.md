# PR — пакет 39 (с59): RF-05 гейт міграцій без fail-open + подія журналу на скидання пароля

Дата: 07.09.2026. Гілка `dev` → `main`. Міграцій НЕМАЄ (прод лишається на 0179, `checked` 21).

## 1. Що було (заміряно, не з доків)

`scripts/migration-gate.mjs` (вшитий у `npm run build` як `--build`) мав ДВА обходи, обидва мовчазні:

1. `RADFLOW_SKIP_MIGRATION_GATE=1` → `WARN` і `return` у БУДЬ-ЯКОМУ середовищі, зокрема у прод-збірці Vercel. Перевірявся ДО ключів і ПІСЛЯ `loadEnvLocal()` — тобто взводився і рядком у `.env.local`.
2. `--build` без `NEXT_PUBLIC_SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` → «мʼякий пропуск» (`exit 0`). Саме на ньому `.github/workflows/gate.yml` (без секретів) проходив КОЖЕН прогін — і `AGENTS.md` радив «повний гейт на клоні» саме в цьому режимі, де леджер не звіряється.

Прод при цьому був у порядку: build-лог с58 показав `[migration-gate] OK: 179/179` (ключі на Vercel є, змінної обходу немає). Тобто діра не «горіла», але жила один рядок від «горить» — одна змінна в дашборді або одна прибрана змінна зі scope Preview, і прод-збірка збиралась би БЕЗ звірки, з `WARN`, який ніхто не читає.

Другий борг — з ревʼю Б пакета 38: після RF-09 єдиний «гучний» шлях до чужого акаунта (адмін будь-якого центру CEO → `reset` → свіжий токен → вхід) не лишав у журналі важливих подій НІЧОГО, крім `password_set=false` у `profiles`.

## 2. Що зроблено

### 2.1 RF-05 — рішення чистою функцією

`scripts/migration-gate-lib.mjs` → `gateEnvDecision({buildMode, vercel, skip, noDb, hasUrl, hasKey}) → {action: run|skip|fail, message}`. CLI (`migration-gate.mjs`) бере рішення ДО першого запиту в базу: `fail` → `console.error` + `process.exit(1)`, `skip` → `console.warn` + `return`, `run` → як раніше.

| середовище | skip | noDb | ключі | дія |
|---|---|---|---|---|
| Vercel (`VERCEL=1`) | будь-що | будь-що | будь-що | **fail**, окрім «нічого не просять + ключі є» → run. Порядок повідомлень: skip → noDb → ключі (оператор бачить САМЕ ту змінну, яку поставив) |
| поза Vercel, `--build` | 1 | — | — | skip, `WARN … БЕЗ ЗВІРКИ` (аварійний обхід, лишено свідомо) |
| поза Vercel, без `--build` (`db:gate`, `db:gate:check`) | 1 | — | — | **fail** — перевірку не обходять |
| поза Vercel, `--build`, без ключів | 0 | 1 | немає | skip, `SKIP … БЕЗ ЗВІРКИ` (CI без секретів — ЯВНО) |
| поза Vercel, `--build`, без ключів | 0 | 0 | немає | **fail** із підказкою про `RADFLOW_GATE_NO_DB=1` (раніше — мовчазний exit 0) |
| поза Vercel, без `--build`, без ключів | — | будь-що | немає | fail (як і було) |
| ключі є, нічого не просять | 0 | будь-що | є | run (`noDb` при ключах ігнорується — безпечний напрямок) |

`.github/workflows/gate.yml`: крок `build` отримав `env: RADFLOW_GATE_NO_DB: "1"` — пропуск названий у workflow і в лозі. Заголовок yml більше не каже «мягкий пропуск (проверено)».

`VERCEL` — факт середовища (Vercel ставить його сам у кожній збірці, і в Preview теж), не налаштування. Підробити локально можна — це лише зробить локальну збірку суворішою.

### 2.2 Подія журналу на скидання/встановлення пароля

`app/api/staff/password/route.ts`: після ОБОХ записів (auth + profiles) — `emitImportantEvent({eventType: "staff.access_changed", entityType: "staff", entityId: target, clinicId: me.clinic_id, details: {action: password_reset|password_set, targetRole}})`. Токен і пароль у details не потрапляють ні під яким ключем (тест шукає їх як РЯДКИ у всіх аргументах). `emitImportantEvent` не кидає (повертає boolean, лог у `logError`) — відповідь роута не залежить від журналу.

`clinicId` — центр АДМІНА (CEO має `clinic_id NULL`); там подію бачить адмін і сам CEO за активним грантом (`imp_events_read_ceo`, 0128). Адміни ІНШИХ центрів того ж CEO її не бачать — названа межа, не дефект.

Знайдено тестом у першій редакції: роут деструктурував лише `{ me }` з гейта → `ReferenceError: user is not defined` на КОЖНОМУ виклику. Виправлено (`const { user, me } = gate`), мутація C5 стенда це пінить.

`lib/journalText.ts` (ревʼю Б: роль цілі — і є сенс події):

| подія | заголовок (актор — адмін) |
|---|---|
| `password_reset`, targetRole `ceo` | Адміністратор скинув пароль **керівника** |
| `password_reset`, `referrer` | Адміністратор скинув пароль **направника** |
| `password_reset`, персонал / без ролі | Адміністратор скинув пароль співробітника |
| `password_set`, `ceo` / інші | Адміністратор встановив пароль керівника / співробітника |

Фільтр журналу — за ТИПАМИ подій (`staff.*` → «Доступи та інше»), нових пунктів не потрібно.

## 3. Ревʼю — дві лінзи, знахідки і що з ними

**А (фальсифікація — «яка мутація лишає піни зеленими»)**: MAJOR однорядковий `return` до рішення невидимий для піна → новий тест + B5; MAJOR двійник не вміє відмовляти в GoTrue → `authUpdateError`, тест, C11; MAJOR гейт гранту CEO без негативних тестів → 3 кейси `it.each`, C8/C9, сусід у таблиці + C10; MINOR `clinicId` у CEO-тесті не пінився → пін + C12; MINOR C2 дублював, а не переносив → `edits`; MINOR `VERCEL: ""` ≠ unset → `delete`; NOTE `hasUrl` пін лише за присутністю → regex + B6. Відхилено: «передати недосяжний URL у підпроцес» — це зробило б B1 (CLI без `exit(1)`) ✅ з хибної причини (падіння на `createClient`), а не через гейт. Названо як борг: `lib/importantEvents.ts` PII-список не має `password`/`pw` (дзеркало CHECK-у БД — потребує міграції); `profiles.update` після auth-запису ігнорує помилку (до пакета).

**Б (операції — «що зламається у наступного на Vercel/CI/машині»)**: MAJOR `AGENTS.md` радив гейт на клоні без ключів — тепер це exit 1 → два абзаци переписано (`RADFLOW_GATE_NO_DB=1 npm run build` на клоні); MAJOR `ROLLBACK.md` для 0142 пропонував `RADFLOW_SKIP_MIGRATION_GATE=1` як спосіб утримати збірку — на Vercel це тепер поклало б прод → виправлено; MINOR заголовок журналу ховав роль цілі → «керівника/направника/співробітника» + C13; NOTE yml-коментар натякав, що `RADFLOW_GATE_NO_DB` треба прибирати при додаванні секретів — при ключах він ігнорується, уточнено. Перевірено: Vercel prod (ключі є) → `run`, як у с58; Preview з міграцією попереду леджера → fail (так було і раніше — ключі у Preview є); CI: `npm test` ганяє підпроцесні тести без ключів і без мережі, `build` → SKIP «БЕЗ ЗВІРКИ»; `npm run build` на машині власника — без змін.

Міграцій немає — у БД перевіряти нічого. Код: (1) відпечаток `/login` після мержу; (2) build-лог Vercel мусить і далі містити `[migration-gate] OK: 179/179` — тобто рішення `run` на проді (а не skip і не fail). Подія журналу — з'явиться при першому реальному скиданні пароля; штучно скидати пароль живому користувачу заради перевірки не стали (незворотно для нього).
