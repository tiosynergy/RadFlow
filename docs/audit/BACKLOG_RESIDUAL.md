## ✅ Закрыто

- **C-1** операционный журнал изменений — `audit_log` на `queue_entries`+`incidents` (0053).

- **H-2** оптимистичная блокировка переходов статуса — CAS `expectedFrom` (без миграции).
- **M-7** единый `requireRole()` guard для service-role роутов (без миграции).
- **M-1** валидация `incidents.status`/`reason` (0056).

## ⏳ Осталось — с триггером «когда»

### Когда подключаешь n8n (Stage-2)
- **Активация H-1:** заполнить `N8N_WEBHOOK_URL`+`N8N_WEBHOOK_SECRET`+`CRON_SECRET`, вернуть cron в `vercel.json`, включить дедуп по `Idempotency-Key` в сценарии n8n.
- **M-4** offline/online-конфликты: сейчас модель «online-only, last-write-wins». Если появятся планшеты у кабинетов с нестабильной сетью — очередь операций с idempotency-key. Иначе — принять «online-only» как ограничение.

### Когда пойдёт рост (сотни центров / крупная история)
- **M-5** партиционирование `queue_entries` по `scheduled_date` + перенос холодной истории. Триггер: ~10–50M строк или заметный bloat/замедление досок.
- **M-6** `REPLICA IDENTITY FULL` усиливает WAL и realtime fan-out. Триггер: рост объёма WAL / лага Realtime — тогда сузить payload или перейти на broadcast-from-database.
- **M-3** thundering-herd: при сбое Realtime все клиенты разом уходят в полный refetch. Триггер: много одновременных клиентов — добавить jitter + инкрементальный merge по `payload.new/old`.
- **L-1** составной индекс `(clinic_id, scheduled_date, status)`. Триггер: если профилировка досок покажет узкое место (микрооптимизация).

### Базовая гигиена данных (не срочно, но желательно)
- **M-2** ретенция PII: периодически чистить/анонимизировать `queue_entries`, `audit_log`, `event_outbox` старше N мес. (в 0053/0055 есть готовые `delete ...`-заметки). Опереться на шифрование-at-rest Supabase (задокументировать). `pgcrypto` — по желанию.
- **L-4** prune `rate_limits` (растёт без TTL) — `pg_cron`.

### По желанию (низкий приоритет)
- **H-3** сохранение провенанса: `ON DELETE RESTRICT` + soft-delete (`archived_at`) для `rooms`/`profiles`, чтобы удаление не обнуляло историю. Не потеря данных пациента, а качество отчётности.
- **L-2** `rooms.schedule` (JSONB) — `CHECK (jsonb_typeof(schedule->'breaks') = 'array')`.
- **M-7 тест:** покрыть `requireRole()` юнит-тестом, когда в проекте появится тест-раннер (сейчас его нет).
