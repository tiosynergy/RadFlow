## Чому на гілці, а не в `dev`

Гейт СИМЕТРИЧНИЙ (`scripts/migration-gate-lib.mjs:82-88`). Заміряно 13.09:
з файлом `0191_fn_bodies_acl.sql` на диску і без рядка в леджері
`npm run db:gate:check` дає **«ЗУПИНЕНО — розходження диск ↔ леджер (1)»**,
тобто `npm run build` червоний, тобто прод не збереться. Файл міграції може
лежати в `dev` тільки разом із накатом. Тому машинерія живе на гілці, а `dev`
і `main` лишились зеленими.

## Що робить

| # | зміна | що тепер видно |
|---|---|---|
| 1 | `;acl=` в `attrs` — у виразі `cur` і в усіх 30 старих рядках | прямі гранти/revoke на будь-якій із 33 функцій |
| 2 | три нових піни: `auth_can_refer(c uuid)`, `auth_referrer_visible_rooms()`, `auth_referrer_clinics()` | ЗНАЧЕННЯ їхнього `search_path`, волатильність, мова, власник, права |

`;acl=` рахується так:
```sql
case when p.proacl is null then '<default>'
     else coalesce((select string_agg(t, ',' order by t collate "C")
                      from unnest(p.proacl::text[]) t), '<empty>') end
```
Три форми на всі 33: **STAFF 7**, **PUBLIC 10**, **TRIG 16** (друкує сам збирач).

## ⚠️ Підстава переписана після двох ревʼю і заміру

Перша редакція шапки стверджувала: тіла трьох вирішувачів «можна переписати
при 23 зелених перевірках». **Це було неправдою.** Обидва ревʼю знайшли це
раніше за автора, обидва з посиланням на рядок.

**Заміряно зондом у відкоченій транзакції** — псували тіло, дивились, хто
почервонів:

| зіпсовано | хто помітив |
|---|---|
| `auth_can_refer` | `grant_digest` (№22) |
| `auth_referrer_visible_rooms` | `grant_digest` (№22) |
| `auth_referrer_clinics` | `grant_digest` (№22) |
| `auth_can_see_slot_details` | `guard_fn_bodies` (№19), і ЛИШЕ він |

№22 фільтрує definer-функції по досяжності `anon`; усі три нових — форми
PUBLIC, тобто в її одинадцятці, і пінить вона ПОВНИЙ сирий md5 — суворіше за
нормалізований у №19. У `auth_can_see_slot_details` гранта `anon` немає — тому
знахідка 0190 справжня, а «поверх вище» — ні.

**А ось чого не бачив НІХТО** (той самий зонд):
```
alter function public.auth_can_refer(uuid) set search_path = pg_temp, public
→ жодна з 23 перевірок не почервоніла
```
Для SECURITY DEFINER це підручниковий вектор ескалації. №2 вимагає лише
НАЯВНОСТІ підрядка `search_path`; №22 `proconfig` не читає; значення стереже
саме `cfg=` в `attrs` списку №19 — куди ці три не входили. **Ось справжня
підстава пакета.** Тіла дублюються з №22 навмисно: покриття №22 зникає того
дня, коли функція втрачає anon-досяжність.

## Що дали ревʼю (обидва — до збірки фінальної редакції)

**Ревʼю А (фальсифікація):** блоковий коментар обходив тест (фільтр знімав лише
`--`); `<default>` склеював `proacl IS NULL` і `{}`; `order by` без `collate`;
CR і багаторядкові якорі; `auth_referrer_clinics` — четвертий вирішувач того
самого доступу; шлях звіту №19 не пінований; `proacl` не бачить членства в
ролях (і коментар у тесті стверджував протилежне).

**Ревʼю Б (перебільшення + операційний ризик):** центральна теза шапки хибна
(див. вище); `0191_rollback.sql` не існував, хоча на нього посилались два
файли; «жодного grant/revoke» правда про файл і неправда про накат; роль-грантор
не названа; `lock_timeout` обмежує очікування, а не утримання; `npm test`
звіряє ФАЙЛ, не базу.

**Усе назване виправлено**, крім свідомо залишених межей нижче.

## Названі межі (жодна НЕ закрита)

1. `proacl` несе лише ПРЯМІ гранти — членство в ролях невидиме обом сторожам.
2. `nspacl` схеми і `alter default privileges` не входять нікуди.
3. Нова definer-функція з грантом лише `authenticated` невидима і №19, і №22.
4. Шлях звіту №19 (`) x;` → обробник → `if v_tmp is not null`) не пінований
   тестом: `where x.txt not like 'attrs:%'` вирізає весь приріст цієї міграції.
5. Гілки `<default>` і `<empty>` червоним базисом не перевірені — серед функцій
   схеми сьогодні немає ані NULL-proacl, ані порожніх.
