# Аудит 2026-07-11 — запись в прошлое + UX-ошибкоопасность

Повод: владелец обнаружил, что систему можно заставить записать/перенести пациента на **уже прошедшее время**.

---

## Часть 1. Запись в прошлое — ЗАКРЫТО (код в `dev`, миграция 0063)

### Корень (почему «при создании ок, а при переносе — нет»)

`RescheduleModal` проверяла прошлое так:

```ts
const isToday = dateStr === clinicTodayStr;
if (isToday && a < nowMin) return "past";
```

Дата вводится обычным `<input type="date">`; атрибут `min` в браузере **ничего не блокирует** (значение можно ввести/вставить). Любая дата ≠ сегодня → `isToday = false` → проверка `past` **не выполнялась вообще** → весь прошедший день рисовался свободным, кнопка «Перенести» активна. Касалось **всех ролей** (модалку открывают админ, регистратор и направитель), просто первым заметили у направителя.

При **создании** дыры не было: там календарь-компонент с `disabled` на прошедших днях.

### Что было ещё хуже

**Ни сервер, ни БД не проверяли время вообще.** `createBooking`, `createReferralBooking`, `rescheduleQueueEntry` не сравнивали слот с «сейчас»; CHECK/триггера в БД не было. Вся защита была клиентской → прямой вызов Server Action (в т.ч. направителем) создавал запись в прошлом.

### Фикс — три слоя

1. **Сервер** (`app/queue/actions.ts`): `isPastSlot()` — «сейчас» в **настенном времени клиники** (`clinics.timezone`, канон 0035/0059), допуск **5 мин** (панель коллизий законно ставит запись на ближайшую пятиминутку). Новый код ошибки `past`. Подключено в три write-пути.
2. **БД** (`0063_no_past_slots.sql`): триггер `trg_b_not_in_past`. Имя с `_b_` намеренно — BEFORE-триггеры идут по алфавиту, а `scheduled_at` авторитетно пересчитывает `trg_a_set_scheduled_at` (0035); нам нужно уже пересчитанное значение. Терминальные статусы и UPDATE без смены слота пропускаются (иначе сломались бы правки старых записей).
3. **Клиент**: прошедший день закрыт целиком (`isPastDay`) в `RescheduleModal`, `BookingModal`, `ReferralPortal`; дата клампится в `onChange`.

### Побочно закрыт класс багов «смешанные системы времени»

`BookingModal` считал `nowMin` по таймзоне **клиники**, а «сегодня» (`today0()`) — по **браузеру**. В центре другой зоны это либо отключало проверку прошлого, либо срезало будущее. Теперь один фрейм: `clinicToday` из `wallNow(tz)`; `BookingCalendar` принимает `today` пропом. `WaitlistBoard` вообще не вызывал `setClinicTz` → «сейчас» считалось по браузеру; теперь грузит зону и передаёт её явно.

**Правило на будущее:** любое сравнение «сейчас vs слот» — только через `wallNow(clinics.timezone)`. `wallNow()` без аргумента молча падает на зону браузера — это ловушка.

## Часть 2. Находки

### P0 — ВСЕ ЗАКРЫТЫ (2026-07-11, код в `dev`, миграции не нужны)

1. ✅ **График кабинета из Мастера НИГДЕ не применялся** → `roomScheduleFor(date, roomId, override, roomSchedule)`: приоритет override → `rooms.schedule` (days / perDay / dayHours) → дефолт. Прокинут во все сетки слотов, гарды вызова, карточки кабинетов и редактор графика на дату (там «типово» больше не значит «Пн–Сб 08–18»). Страницы селектят `rooms.schedule`. Воскресенье в календаре больше не блокируется жёстко — день закрывает график кабинета. **+ серверный гард `isOutsideRoomSchedule()`** в `createBooking` / `createReferralBooking` / `rescheduleQueueEntry` (код `off_schedule`): UI-фикс сам по себе ничего не гарантирует — устаревшая вкладка или прямой вызов Server Action всё равно записали бы в закрытый кабинет.
2. ✅ **Удаление кабинета молча отвязывало записи** → `SetupWizard` считает активные записи (`scheduled/waiting/in_progress`) удаляемых кабинетов **до** любых записей в БД и блокирует сохранение с перечнем.
3. ✅ **Ошибка загрузки = «пусто»** → `QueueBoard`: `entriesErr` (отдельное состояние вместо «Записів немає» + баннер «Черга не оновилась», если старые строки на экране), `incidentsErr`/`overridesErr` — **раздельные** (общий флаг затирался тем загрузчиком, который ответил последним) → баннер + **«Новий запис» блокируется**, пока данные о простоях/графиках ненадёжны. Прежние данные не затираются.
4. ✅ **Портал направителя: сбой загрузки занятости = «всё свободно»** → `slotsErr`, сетка не показывается. Ошибки RPC/override/incidents больше не глотаются (PostgREST не бросает сам — `if (error) throw error`).
5. ✅ **Отмена записи в один клик** → `ConfirmDialog` на всех путях: доска, колл-лист («Відмова» + `onRefuse` в секции простоя), портал. **Важно:** «✕ Відмова» (`call_status='declined'`) на сервере **отменяет запись** — диалог теперь прямо это говорит и предлагает «Не відповідає»/«Передзвонити» как альтернативу. У аварийной остановки убран `hideCancel`.

Известный остаток: `dayStatus()` / `MiniCalendar` всё ещё считают выходным только воскресенье (не знают про `rooms.schedule`) — метки в мини-календаре могут расходиться с реальным графиком. Не опасно (запись гейтится сеткой и сервером), но требует правки.

## Часть 3. Открытые находки (НЕ исправлены)

### P0

1. **График кабинета из Мастера настройки НИГДЕ не применяется.** `roomScheduleFor(date, roomId, override)` (`lib/schedule.ts:40`) не принимает `rooms.schedule` вообще: эффективный график = хардкод «Пн–Сб 08:00–18:00» + `schedule_overrides`. `SetupWizard` при этом честно сохраняет `days[]`, `start/end`, `perDay`, `dayHours` — читаются оттуда **только** `breaks[]`. Админ настроил КТ «Пн–Пт 09:00–15:00» → система всё равно предлагает субботу и слоты до 18:00. **Пациента запишут на время, когда кабинет закрыт.**
   Фикс: сигнатура `roomScheduleFor(date, roomId, roomSchedule, override)`, приоритет override → rooms.schedule → дефолт; обновить ~6 вызовов.

2. **Удаление кабинета в Мастере отвязывает записи пациентов молча.** `queue_entries.room_id` — `on delete set null` (0001): записи остаются с `room_id = NULL`, пропадают из room-view, их нельзя вызвать в кабинет. Подтверждения нет, тост «Зміни збережено». (`incidents`/`radiologist_rooms` — `cascade`, тихо исчезают.)

3. **Ошибка загрузки = «пусто/всё хорошо» во всех досках.** `loadIncidents` при ошибке → `[]` → **заблокированный кабинет выглядит свободным** (можно записать в сломанный аппарат); `loadOverrides` → `{}` → закрытый день выглядит рабочим; `reload` → «Записів немає». Нужно различать `error` и `empty` (в `BookingModal`/`RescheduleModal` это уже сделано для `busyError`).

4. **Сетка слотов у направителя не защищена от сбоя загрузки занятости** (`ReferralPortal`: `data || []`, гейт только по `slotsLoading`) — при падении RPC весь день выглядит свободным.

5. **Отмена записи — в один клик, без подтверждения** (доска, колл-лист, портал). В колл-листе кнопка называется «Відмова», а переводит запись в `cancelled` — узнаёшь из тоста постфактум.

### P1

6. `editQueueEntryStudies` принимает любой `durationMin` — исследование можно растянуть за конец графика и в перерыв (сервер не проверяет; ловит только триггер пересечения).
7. Степпер позволяет прыгнуть сразу в «Виконано» для пациента, который не приходил (растёт «Дохід» у CEO).
8. `StudyEditModal` завышает доступное время, пока грузится занятость (`capByNext = Infinity`).
9. «✓ Всіх підтверджено» в колл-листе подтверждает **всех** за день, игнорируя фильтр, без подтверждения; тост об успехе даже при 0 обновлённых строк.
10. «▶ Відновити роботу» снимает аварийную остановку со **всех** кабинетов, хотя в модалке перечислены конкретные.
11. Аварийная остановка считает «пострадавших» по **браузерному** дню (`dateKey(new Date())`).
12. Некорректные перерывы/часы молча выбрасываются при сохранении графика; часы `18:00–08:00` сохраняются и сетка слотов просто исчезает.
13. Правила статусов расходятся: у радиолога на прошедшей дате можно двигать статусы, у админа — нет.
14. Воскресенье жёстко запрещено к записи, но разрешено к переносу.
15. Тач-таргеты 5-минутной сетки ~15×22 px (ниже WCAG 24px и собственного правила ≥40px); состояние занятого слота живёт только в `title=` — на тач-устройствах недоступно.
16. Желаемое окно листа ожидания можно задать в прошлом → пациент вечно висит в «Очікують».

### P2

17. `StatusBadge` в колл-листе различает статусы только цветом (1.4.1).
18. Тосты без `aria-live` в `QueueBoard`/`CallListBoard`.
19. Тост «Пацієнт відмовився — запис скасовано» рисуется **зелёным** (успех).
20. Горячие клавиши работают под открытой модалкой аварийной остановки.
21. `SetupWizard` при каждом «Зберегти» перезаписывает `clinics.timezone` зоной браузера оператора (поля в UI нет!) — от этой зоны зависят «Запізнення», «Уточнити» и гарды старта.
22. Смена типа кабинета (МРТ↔КТ) без предупреждения о существующих записях.
23. CSV колл-листа без защиты от формульной инъекции.
24. `scheduledAt` — мёртвый непроверяемый вход в 3 Server Actions (БД всё равно пересчитывает через `set_scheduled_at`); убрать из типов.
25. Нет DB-гарда «room_id принадлежит clinic_id» для `queue_entries` (для `waitlist_entries` он есть — 0051).
