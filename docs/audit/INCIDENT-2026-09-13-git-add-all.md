# Инцидент 13.09.2026 — `git add -A` подмёл чужую правку в `main`

**Виновник: сессия 67.** Не «так получилось» — конкретная команда.

## Что произошло

В `D:\RadFlowDev` параллельно работали ДВЕ сессии: с67 (документы аудита) и
с68 (мутации B5–B9, закрывающие названные межи 6–8 аудита 0191). Дерево одно.

Коммит **`ccfc322`** («план аудита: снят ложный довод „это медицинские данные“»)
сделан командой `git add -A` и захватил, кроме своего документа, ещё два файла
сессии с68 **в промежуточном состоянии**:

* `scripts/falsify-0181.mjs`
* `tests/guardFnBodiesInvariant.test.ts`

Коммит смёржен в `main` (**`9961575`**) и запушен.

## Замер состояния, которое уехало

| что | значение | следствие |
|---|---|---|
| `EXPECTED_RED` в `falsify-0181.mjs` | **17** | |
| мутаций в файле | 20, из них `green: true` — 4 | красных **16** |
| 17 против 16 | | стенд умирает на входе: «ІНВЕНТАР БРЕШЕ: адресних мутацій 16, а очікується 17. Стенд НЕ прогнано» |
| тест «атрибути несуть НАЗВАНІ поля» | **удалён** | |

То есть работа с68 корректна по замыслу и не дописана по факту: мутации есть,
тесты под них ещё не написаны. Это нормальное промежуточное состояние — ровно
то, что не должно попадать в коммит чужой сессии.

## Чего инцидент НЕ сломал

**Прод не затронут.** `npm run build` — это гейт миграций плюс `next build`;
`vitest` в сборку не входит (ревью с50). Гейт зелёный 191/191, файл 0191 в
`main` лежит, деплой `27d067974923` живой, `/login` 200. Сломаны тесты и стенд
в ветках, а не production.

## Решение владельца

`ccfc322` **оставить**, историю не переписывать (append-only; переписывать
запушенный `main` хуже самой проблемы), пояснение — этим файлом.
Сессия с68 допишет тесты и сведёт `EXPECTED_RED` своим коммитом поверх.

## Правило, которого не хватало

⚠️ **`git add -A` запрещён, когда дерево может быть не только твоим.**
Перечисляй свои файлы поимённо:

    git add docs/audit/МОЙ-ФАЙЛ.md
    git commit -F .commitmsg

Все коммиты с67 до этого делались именно так (`git add scripts/falsify-0181.mjs
scripts/falsify-0182.mjs scripts/falsify-0183.mjs`) — и ровно там, где я
переключился на `-A`, случился инцидент.

⚠️ **«Дерево было чистым» — не индульгенция.** Оно ДЕЙСТВИТЕЛЬНО было чистым на
`e759123` (19:26), и это проверено и записано. Правки с68 легли между 19:26 и
коммитом. Проверка чистоты говорит о ПРОШЛОМ, а `-A` берёт НАСТОЯЩЕЕ.

⚠️ Соседний класс, уже известный проекту: «любая правка в репозитории, пока
идёт стенд, молча откатывается» (с58, с64). Там чужая рука ломала мой прогон,
здесь моя команда забрала чужую работу. Общий корень один — **дерево общее, а
инструменты об этом не знают**.

## Что должна знать сессия с68

Твои B5–B9 **уже в `main`** (`ccfc322` → `9961575`) в промежуточном виде. Это
не твой коммит и не твоё сообщение. Допиши тесты и сведи `EXPECTED_RED` с числом
красных мутаций обычным порядком — конфликта не будет, рабочее дерево никто не
трогал.
