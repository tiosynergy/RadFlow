## 3. Ризик каталогу — знайдено і знято ДО вставки

`check_studies_active_catalog` має legacy-виняток: якщо для модальності немає **жодної**
видимої послуги, каталог не обмежує. КТ і УЗД у Medicom були саме в такому стані
(0 послуг), і **15 КТ + 8 УЗД region-назв уже вживались у наявних 98 записах**.

Якби послуги завели «з голови», виняток закрився б, і **будь-яке редагування досліджень
або перенос у інший кабінет цих наявних рядків падав би з `SERVICE_CLOSED`**.

**Що зроблено:** усі 23 послуги створено НЕ вручну, а `INSERT … SELECT DISTINCT` з
живих `queue_entries.studies` — тобто назви збіглись побайтово (включно з `’` U+2019 у
«УЗД м’яких тканин»). `duration_min` = max фактичної тривалості, округлення до 5;
`price` = тривалість × 60 (КТ) / × 45 (УЗД); `contrast_allowed` = true для назв із
«контраст» / «ангіограф».

**Перевірка після вставки:** КТ/УЗД рядків, що не резолвляться в активну видиму послугу — **0**.

## 6. Прибирання (перевірено прогоном із відкотом)

```sql
delete from public.queue_entries where note like '%[seed-2026-09-08]%';   -- 192
delete from public.patient_cases  where note like '%[seed-2026-09-08]%';  -- 12
delete from public.services
 where source='seed' and clinic_id='c79588d6-c379-4949-9c23-a22c227a12e1'; -- 23
```

Прогнано в `begin; … rollback;`: усі три DELETE пройшли, `invariants_check(false)` після
них — `{ok:true, checked:22, failed:[]}`.

Два застереження:

1. **Послуги видаляти лише ВСІ 23 разом.** Видалення частини залишить модальність
   «не-legacy» і зламає наявні КТ/УЗД рядки. Видалення всіх — повертає legacy-виняток,
   наявні рядки лишаються робочими (саме це показав відкат).
2. **З UI видалити не вийде** — `guard_no_client_delete` забороняє DELETE клієнтським
   ролям (запис скасовують, а не видаляють). Прибирання — лише сервісною роллю / MCP.

«Головний мозок», «Черевна порожнина», «МР-ангіографія вен головного мозку».

назви. У план поточної сесії не входила.
