## Дефект: галочка, яку не можна було побачити

Правило 0077 дозволяє персоналу центру подовжити дослідження за межу графіка
або в перерву — за явним підтвердженням. Серверний гейт це реалізує:

```ts
if (!info) return { blocked: null, offSchedule: false };  // у межах графіка
if (!info.confirmable) return { blocked: offSchedError(info) };   // нікому
if (!opts.isStaff) return { blocked: OFF_SCHED_ERR };             // направнику
if (!opts.offSchedule) return { blocked: offSchedNeedsConfirm(info) };
return { blocked: null, offSchedule: true };
```

Клієнт мав відповідну галочку — і вона була **недосяжна**. Умова була:

```ts
const crossesNow = totalDur > inSchedCap;
const needsOffConfirm = crossesNow && !overflow && allowOffSchedule;
```

Для запису, що стоїть **у графіку**, обидві пари стель збігались тотожно:
`capBySched === capBySchedStrict` і `capByBreak === capByBreakStrict`, бо grace
відкривав лише прапорець `offSchedule` самого запису. Отже
`availableDur === inSchedCap`, отже `crossesNow ⟺ overflow`, отже
`crossesNow && !overflow` — **тотожний false**. Персонал бачив «⚠ Не
вміщується» і сіру кнопку там, де сервер подовження ДОЗВОЛЯЄ. Це той самий клас
провалу, що U-12, лише з іншого боку: там клієнт обіцяв те, чого сервер не дасть,
тут — ховав те, що сервер дає.

Поруч жили ще два з тієї ж родини:

* **U-21.** `closed` / `before_start` / `too_late` сервер відхиляє гілкою
  `!info.confirmable` **раніше за роль** — тобто нікому. Клієнт про вид не знав
  нічого: `offForbiddenForRole` завʼязаний лише на роль, тож персоналу кнопка
  лишалась активною, а сервер відмовляв уже після натискання.
* **U-22.** Перерва, що вже **триває** на момент старту, у стелі не потрапляє
  (`nextBreakStart` фільтрує `m > startMin`). `crossesNow` лишався false, згоди
  ніхто не питав, і сервер відповідав «потрібне підтвердження» формі, яка не
  мала способу його дати. Глухий кут.

## Правка: питання ставимо тій самій функції, що й сервер

Три дефекти закриває одна структурна зміна: рішення про згоду більше не
виводиться з арифметики стель, а читається з `offNow` — результату
`offScheduleKind`, тієї самої чистої функції, яку зве серверний `scheduleBlock`.

```ts
const offAllowed = offSchedule || allowOffSchedule;   // grace відкриває і РОЛЬ
const offHardBlocked = !!offNow && !offNow.confirmable;
const needsOffConfirm = allowOffSchedule && !!offNow && offNow.confirmable && !overflow;
const offForbiddenForRole = !allowOffSchedule && !!offNow;
const offDeadEnd = offForbiddenForRole || offHardBlocked;
```

`offAllowed` — саме дизʼюнкція, а не заміна: успадкований прапорець мусить
піднімати стелю й тоді, коли роль овертайму не має (направник відкриває запис,
що вже стоїть поза графіком), інакше повертається провал №1 з U-12.

Для U-22 строга стеля навчилась бачити перерву, що накриває старт:

```ts
const curBreak = schedApplies ? roomBreaks.filter(b => b.start <= startMin && startMin < b.end)
  .sort((a, b) => end(b) - end(a))[0] : undefined;
const capByBreakStrictRaw = curBreak ? 0 : capByBreakRaw;
```

Нуль іде **лише** в строгу стелю: у мʼяку він перетворив би чесну відмову на
«⚠ Не вміщується, скоротіть», а скорочення там не рятує.

## Два раунди ревʼю: 24 находки, 13 прийнято, і всі 13 — регресії САМОЇ правки

Це найяскравіший приклад правила «бюджет пакета = фікс + пʼять внесених ним
дефектів» за весь час: **жодна** прийнята находка не була старим дефектом.

### Раунд 1 (сервер+ролі / стани UI)

1. **Підпис межі осліп.** `boundaryLabel` обирав гілку «до перерви о HH:MM» за
   умовою `capByBreak <= capBySched`. Відколи grace робить `capByBreak = Infinity`
   для персоналу, `Infinity <= capBySched` тотожно false — гілка вмерла, і межу
   13:00 екран підписував словами «до кінця графіка (18:00)». Той самий напис їхав
   у банер згоди: «вийде за межу (**13:00**: до кінця графіка (**18:00**))».
   Фікс: підпис описує СТРОГУ межу, тож і читає строгі стелі.
2. **Направнику пообіцяли овертайм.** `overtimeRoom = availableDur > inSchedCap`
   без перевірки ролі: направник із успадкованим `off_schedule` читав
   «Понаднормово — до 180 хв з підтвердженням», якого його роль дати не може
   ніколи. U-12, заведений заново через нове речення.
3. **Сумарна тривалість не клампилась `DUR_MAX`.** Сервер нормалізує через
   `normDur`, який **мовчки** ріже до 480: склад на 500 хв зберігся б із
   `duration_min = 480` і розійшовся б із самим `studies[]`. Відколи стеля
   виросла на grace, цей діапазон стало легко набрати.
4. **Банер «не може погодити ніхто» ховався за `!overflow`.** У закритому дні з
   довгим складом екран казав тільки «Скоротіть на N хв»; оператор скорочував —
   і аж тоді бачив «кабінет цього дня не працює». Двокрокова брехня. Направник
   такого гарда ніколи не мав, тобто персонал був поінформований ГІРШЕ за нього.
5. **«У графік вміщується N хв» для закритого дня.** `roomScheduleFor` для
   закритого дня повертає дефолтні 08:00–18:00, тож екран писав червоним «Разом
   30 хв. У графік вміщується 330 хв» із сірою кнопкою — читач робив висновок
   «усе влазить». Фікс: `lengthIrrelevant` — для `closed`/`before_start` число
   не друкується взагалі, називається причина.
6. **Захист «не підтверджені» обходився.** `labelFor` тримається на
   `cap === committedDur` і мовчить, щойно вʼяже інша стеля: при впалій
   зайнятості екран обіцяв «до 20:00» поруч із банером «збільшувати тривалість
   поки не можна». Фікс: гілка овертайму вимагає `availTrusted`.
7. **Згода переїжджала на іншу причину.** Галочка, поставлена під заїзд в обід,
   лишалась стояти, коли склад ставав `after_end` — і мовчки підписувала
   понаднормову роботу. Фікс: скидання на зміні виду.
8. **«до 24:00» і «до 25:00».** Кабінет до 22:00 + 2 год grace, а `fmt` не
   згортає добу. Фікс: `fmtDay` із переносом.
9. **Банер згоди не називав причину.** Для запису всередині перерви він казав
   «вийде за межу (14:50: до наступного запису о 15:00)» — три неправди поспіль.
   Фікс: `offReasonText(offNow)`, та сама функція, що в банері відмови.
10. **Портал направника не підключав `radflow-screens.css`.** Базові правила
    `.info-banner`/`.ib-txt` живуть саме там, тож ЄДИНИЙ банер, який направник
    узагалі бачить — чесна відмова U-12, — рендерився без коробки. **Дефект
    приїхав із с47 разом із самим банером.**

### Раунд 2 — і він зарубав ПОЧИНКУ раунду 1

11. **`noConsentCap` був гіршим за початковий дефект.** Проміжний варіант
    `noConsentCap = offSchedule ? availableDur : inSchedCap` спирався на
    міркування «для запису поза графіком згода їде з успадкованим прапорцем
    (`save()`: `offSchedule || …`), нової не треба». Це **неправда**: `valid` усе
    одно вимагає `(!needsOffConfirm || offOk)`, а `needsOffConfirm` для такого
    запису істинний при будь-якій довжині. Наслідки: банер писав «Без згоди
    вміщується 60 хв» рівно над обовʼязковою галочкою; `cap > noConsentCap`
    ставало тотожно false — чесна гілка підпису вмирала; `overtimeRoom` тотожно
    false ховало єдину згадку про підтвердження. Три нові дефекти з однієї
    «розумної» ідеї. Прибрано, межа без згоди — рівно `inSchedCap`, а нуль у ній
    отримав власну гілку тексту.
12. **Безумовний пріоритет глухого кута забрав робочу пораду.** Фікс №4 поставив
    `offDeadEnd` перед `overflow` — і для `too_late` (склад довший за grace) екран
    почав слати оператора перезаписувати пацієнта там, де вистачало прибрати
    30 хв: скорочення робить вид підтверджуваним `after_end`. Фікс фікса:
    пріоритет вирішує `lengthIrrelevant`, а не «хто перший».
13. **Скидання згоди спрацьовувало на транзієнті набору.** Щоб замінити «100» на
    «110», оператор набирає «1» — склад на мить вміщується, `offKind` падає в
    `null` і назад, галочка гасне без видимої причини. Фікс: скидання лише на
    переході між двома РЕАЛЬНИМИ видами.

Окремо раунд 2 зняв те, що я додав із добрих намірів: `role="alert"` /
`role="status"` на банерах. Їхній вміст містить сумарну тривалість, а `setDur`
пише сире значення на кожне натискання клавіші — жива область зачитувала б два
абзаци тричі за набір «120», а assertive-роль ще й перебивала б поле вводу.
Напівзроблена жива область гірша за жодну; чесна вимагає озвучення по blur із
нормалізованим числом — заведено як **U-26**.

  рахується лише `hasSlotClash`, і це інший (мʼякий) банер. Розходження
  доправочне, заведено як **U-27**.

  але консервативну стелю невідомості тримає `capBySched`; гілку лишено
  свідомо, з коментарем: без неї наступна правка `capBySched` мовчки зняла б
  fail-closed і для перерв.
