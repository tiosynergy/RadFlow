# PR — с79: CSV дашборда CEO збирає сервер і пише журнал (Н-10)

Дата: 24–25.09.2026. Гілка `s79-n10-ceo-export` (`5e75ccf` → `87aa796` → `c2a8bc8`; на машині
власника — `4d02348` → `e394dc5` → `2600165`) → `dev` → `main d10c6c6`. Міграцій немає.

## 1. Що було (Н-10, `ToDo_Production.md` §3)

`exportCsv()` у `components/CeoDashboard.tsx` читав у браузері під RLS до 5000 рядків
`queue_entries` із ПІБ, процедурою й доходом і складав CSV сам. Події `patient_data.exported`
не було (у xlsx-експорту пошуку — є), екранування формул — лише `= + - @`. Ревʼю знайшло ще
одне: запит `.limit(5000)` одним викликом під PostgREST із `db-max-rows = 1000` мовчки
віддавав не більше 1000 рядків — місячний файл одного центру (≈2,9 тис. записів) був неповним
без жодного сигналу, а каталог для оцінки доходу — теж.

## 2. Що зроблено

* **`POST /api/ceo/export`** (`app/api/ceo/export/route.ts`):
  * гейт `requireRole(null)` + ліміт 10 файлів за 10 хв (`ceo_export`), далі — ТЕ САМЕ правило,
    що гейтить сторінку `/ceo` (`lib/ceoScope.ts`): admin і ceo, будь-яка інша роль — лише з
    активним `ceo_access`; адмін ненастроєного центру — ні. Тотожність сторінки й роуту тримає
    диференційний тест, що викликає справжню сторінку (18 сценаріїв);
  * тіло `.strict()`: період і `scope` («all» або один id центру) — id лише ВИБИРАЄ центр в
    області, обчисленій із сесії; чужий — 403 до читання черги;
  * дані читає RLS-клієнт сесії, service-role — лише для ліміту й журналу;
  * читання сторінками keyset по (дата, id) по 1000 під `db-max-rows`; кінець — порожня
    сторінка; «обрізано» — лише коли 5001-й рядок справді прочитано; при обрізці останній день
    дочитується цілком і зріз іде за (дата, час, id) — «перші 5000» означає «перші за часом»;
    дедуп за id між сторінками; запобіжник 60 сторінок → 500; каталог і кабінети — теж
    сторінками;
  * CSV: BOM, `;`, санітайзер формул (`= + - @`, TAB, CR, повноширинні), CR/LF усередині
    клітинки → пробіл, NUL вирізається (`lib/csv.ts`);
  * журнал: подія `patient_data.exported` у КОЖЕН центр, чиї рядки пішли у файл, лише з ЙОГО
    числом рядків; `details = { source: "ceo_dashboard", rows, format: "csv" }` — ключі вже
    дозволені всіма чотирма лініями захисту ПДн; fail-open, але не мовчки;
  * `Cache-Control: no-store`, `Content-Disposition` з переліку періодів.
* Чисті хелпери (період, каталог, дохід, рядки файлу) — `lib/ceoExport.ts`; ними ж користується
  drill-down дашборда. Пояс «Всі центри» — детермінований (центр із найменшим id).
* Клієнт: `fetch` → blob, ті самі тости, `aria-busy`, 429 і 403 — зрозумілим текстом.
* `lib/journalText.ts`: подія з цим джерелом підписана «з дашборда CEO».

## 3. Ревʼю

* **Раунд 1 (авторизація, область, ПДн, журнал):** High немає; M-1 — обрізка лімітом
  PostgREST (закрито сторінковим читанням); M-2 — диференційний тест не мав сценаріїв
  «радіолог/направник з АКТИВНИМ грантом» (додано); L-1 — перенос рядка в клітинці (LibreOffice
  з комою та EvaluateFormulas робив формулу); L-2 — емісія без `await` не ловилась; L-3 — пояс
  «всі центри» залежав від порядку рядків; L-4 — текст 403.
* **Раунд 2 (сторінкове читання на справжньому PostgREST 12 + PG16, `db-max-rows=1000`):**
  код коректний (7000 записів, межі сторінок, дати без часу, uuid-порядок); дірки в тестах
  (збій на 2-й сторінці, id, що ростуть разом із датою), «перші 5000» випадковою вибіркою
  останнього дня, дубль при переносі запису між сторінками, регістр uuid у двійнику — усе
  закрито, мутації ревʼюера E8/K1/K2/K3/O1 тепер червоні.

## 4. Межі

* Журнал фіксує ОФІЦІЙНИЙ канал: ті самі рядки CEO може прочитати прямим запитом PostgREST під
  RLS (як T10 для пошуку). Замок — область ролі.
* Відмова правила пишеться лише в структурний лог, без `access.denied` у журнал центру (як у
  `/api/search/export`).
* Без знімка: запис, перенесений назад за курсор під час експорту, у файл не потрапить.
* Drill-down дашборда лишився клієнтським (до 1000 рядків із ПІБ без події, помилка каталогу
  там ковтається). `CallListBoard` експортує CSV без санітайзера й журналу — Н-16.
