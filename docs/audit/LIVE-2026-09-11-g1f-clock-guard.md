## Що казала посилка і чому вона хибна

`observeWallStep` (F6, с55) тікає раз на 10 с, помічає крок стінного годинника
і замовляє пробу `rpc("server_now")`; проби від вартового розведені мінімум на
60 с, плюс плановий перезамір раз на 10 хв. Тобто вартовий **звужує** вікно до
десятків секунд, а не закриває його. І він безсилий, коли пробу неможливо
зробити — а це стан, який модуль `serverClock.ts` сам називає штатним: «поки
зсув не виміряно (немає сесії, стара база, збій мережі), зсув = 0 і все
рахується за годинником браузера».

## Рецепт, яким це відтворюється (без переведення системного годинника)

1. DevTools → Request conditions → Block, шаблон **URLPattern**:
   `https://<ref>.supabase.co/rest/v1/rpc/server_now`
   ⚠️ Нова панель DevTools приймає URLPattern, а не підрядок: `server_now`
   не парситься взагалі, а `*/server_now/*` не ловить (URL закінчується на
   `server_now` без слеша).
2. F5 → корректор мертвий, зсув лишається 0, `serverNow()` = годинник браузера.
3. Консоль: `const D = Date.now.bind(Date); Date.now = () => D() - 20*3600*1000;`
4. Лист очікування → «+ Додати пацієнта» → поле «Готовий з» саме переїжджає на
   попередню добу → заповнити обовʼязкові поля, **дату не чіпати** → зберегти.

## 🔴 Замір №1: сдвиг УПЕРЕД на добу гард НЕ ДІСТАЄ

Перша спроба була `+24 год`. Результат: supabase-js вважає access-токен
простроченим, іде `POST /auth/v1/token?grant_type=refresh_token` → **429 Too
Many Requests**, усе інше **401**, застосунок викидає на `/login`.
**До гарда справа не доходить — сесія вмирає раніше.**

Звідси названа межа, якої не було в жодному документі: **область Г1-F — це
зсув, що перетинає північ, але НЕ перевищує залишок життя токена (~година).**
Великий зсув уперед дає не тиху брехню в даних, а вибивання оператора на
екран входу.

Обхід для перевірки: зсув **назад**. Токен тоді виглядає «ще живішим»
(`exp` далі в майбутньому), сесія ціла, а доби розходяться.

## 🔴 ЗНАХІДКА ПРОГОНУ: відмова Г1-F у цьому шляху НЕВИДИМА оператору

Перша спроба червоного прогону виглядала як «натиснув — нічого не сталося».
Кнопка мовчала, у базі нічого не зʼявилось, підказки не було. Причина
знайдена в коді і підтверджена живцем: тост малюється **під оверлеєм
модалки**, і його видно лише коли модалку закрити (Esc).

Це не нова проблема — вона вже названа в тому ж файлі, на сусідній функції:

```ts
// Повертає ТЕКСТ помилки — BookingModal покаже його в собі (тост тонув під оверлеєм).
async function saveBooking(b: BookingSave) { … }
```

Тобто для `BookingModal` це полагодили — відмова повертається текстом і
малюється ВСЕРЕДИНІ модалки. А шлях додавання в лист
(`WaitlistBoard.onAdd` + `WaitlistModal`) лишився на `notify()`:

```ts
if (!res.ok) { notify("Помилка: " + res.error, "error"); return; }
```

**Наслідок:** у рівно тому сценарії, заради якого писався Г1-F, оператор
бачить не пояснення, а мовчазну кнопку. Текст `CLOCK_SKEW_MSG` спеціально
писався так, щоб назвати причину і вихід, — і не доходить.

**Статус:** заміряно, код не чіпано. Окремий пункт черги.
