1 Visibility of system status 8/10

Система должна всегда показывать, что происходит.

Что сделано хорошо

  • Realtime через общий useRealtimeRefetch + обновление по focus/visibility.
  • Skeleton загрузки очереди (aria-busy), loading-gate сетки слотов («завантаження…» вместо ложного «все вільно»).
  • Живые таймеры in_progress, бейджи CITO / Запізнення / Накладення / 🔁 Перенесено.
  • Разделение ошибка ≠ пусто: баннеры entriesErr / incidentsErr / overridesErr, блок «Новий запис» при safetyErr.
  • Stale CAS: тост «Стан змінився — оновіть дошку».
  • Live-счётчик waitlist в сайдбаре; aria-pressed на аварийной остановке.

Находки

IDSevСуть
H1-1 P1 Тосты на QueueBoard / CallListBoard / CeoDashboard — fixed div без role="status" / aria-live. Screen reader и «слепой» оператор не слышат исход действия. Login/Register — ок.
H1-2 P2 Тост 3 с и исчезает; длинная ошибка нечитаема, нет кнопки «закрыть» / «повторить».
H1-3 P2 Toast type: «пацієнт відмовився — запис скасовано» может выглядеть как success (зелёная полоска) — статус системы вводит в заблуждение.
H1-4 P2 После смены статуса строка обновляется, но нет явного progress на кнопке (aria-busy есть в Confirm/export, не везде на board actions).
H1-5 P3 Радиолог: подпись «Архів — лише перегляд», но readOnly = false — UI врёт о режиме.
Рекомендации: единый Toast с aria-live="polite", role="status", duration 5–7 с для error, dismiss; выровнять semantic type (success/warn/error); честный readOnly на прошлых днях у радиолога.

2 Match between system and the real world 8/10

Язык и модель пользователя, не системы.

Что сделано хорошо

  • UI на украинском, клинические термины: «В кабінеті», «Неявка», «Обзвін», «Простій», «CITO».
  • Модальности, кабинеты, «настінний час» клиники — соответствует реальному центру.
  • Сетка слотов: busy vs buffer vs break — отражает реальную занятость аппарата.
  • Панели решения (запізнення, накладення) формулируют действия регистратора, не SQL-статусы.

Находки

IDSevСуть
H2-1 P2 Смесь «Колл-лист» (англицизм) vs «Лист очікування»; «CEO» в меню для UA-клиники.
H2-2 P2 Внутренние коды иногда просачиваются: Помилка: + raw res.error / code-ветки не всегда mapped.
H2-3 P3 Emoji в primary UI (🛑 🔗 🗓 ⏳) — привычно staff, но визуальный шум и разный рендер на Windows.
H2-4 P3 HelpTip про CITO говорит «виносяться вгору», тогда как порядок доски — время → приоритет как tie-break (расхождение product-copy).
Рекомендации: глоссарий UA-терминов; 100% map server codes → human text; обновить HelpTip CITO под реальное правило сортировки.

3 User control and freedom 7/10

Лёгкий выход, отмена, «аварийный люк».

Что сделано хорошо

  • ConfirmDialog на cancel / emergency / confirm-all / case cancel; осмысленные cancelLabel («Залишити» vs «Скасувати запис»).
  • ↩ В чергу после «Виконано» / no-show-пути (частичный undo).
  • Esc + focus trap + return focus (useModalA11y) — отличный control для модалок.
  • Off-schedule: явное согласие в потоке модалки (не nested dialog «кнопка не работает»).
  • Слот «щойно зайняли» → сброс выбора + «Зрозуміло».

Находки

IDSevСуть
H3-1 P1 Нет undo для: смена call_status, приоритета, переноса, правок patient/studies, bulk confirm-all. Ошибку чинят только обратным действием.
H3-2 P2 Тосты не кликабельны; нельзя «відмінити» из snackbar.
H3-3 P2 В кейс-баре портала направителя нет edit шага — только удалить и заново → лишняя работа и риск.
H3-4 P3 Закрытие модалки записи с dirty form — не везде dirty-guard (Setup имеет; Booking — слабее).
H3-5 P2 Hotkeys при emergencyOpen / CaseModal / DelayPlan / waitlist-suggest не в anyModalOpen → n/r/1 срабатывают «под» критичным диалогом.
Рекомендации: расширить anyModalOpen; soft-undo 10 с для call/priority; dirty-confirm на Booking/Reschedule; edit step в referral case-bar.

4 Consistency and standards 6.5/10

Одинаковые слова, паттерны, ожидания.

Что сделано хорошо

  • Единая dark design system (.btn, .badge, .qrow, .dialog).
  • Общие SlotPicker, ConfirmDialog, MiniCalendar, guards computeCallBlock на admin + radiologist.
  • Required fields: .req + красные labels — сквозной паттерн.
  • Login: aria-invalid, blur-validation — эталон форм.

Находки

IDSevСуть
H4-1 P1 Разные toast-системы: inline style vs register.css toast; где-то type color, где-то всегда green border (CEO).
H4-2 P1 Правила статусов: на прошедшей дате админ и радиолог ведут себя по-разному (и у radio readOnly фиктивный).
H4-3 P2 Sidebar: «Новий запис» / «Інциденти» рендерятся всегда; у registrar/роли без handlers — клик в никуда или лишний пункт. Неполная role-фильтрация nav.
H4-4 P2 Call-list status: glyph+color; queue status: badge color; CEO chart red dot — три языка индикации.
H4-5 P2 Expanded row: mix «кнопка primary», «⋯ меню», stepper-кружки — разная affordance для «сменить статус».
H4-6 P3 Плотность: btn-sm min 36px vs 5-min slot cells ~9–12px font / tiny hit area на desktop.
Рекомендации: один notify() / ToastProvider; таблица «роль → действия» в Sidebar; единый StatusChip; выровнять archive-mode на всех досках.

5 Error prevention 9/10

Лучше не дать ошибиться, чем потом чинить. — сильнейшая эвристика продукта.

Что сделано хорошо

  • Disabled + inline reason до клика: call block, no_show до start, safetyErr блокирует new booking.
  • Три слоя past-slot / off-schedule / room schedule.
  • Busy loading fail → сетка скрыта, не «все свободно».
  • Confirm на деструктив; declined = cancel с явным текстом.
  • CAS / stale; unique in_progress; overlap triggers.
  • Catalog gate: нельзя записать на выключенную услугу; AI-import не pre-check галочки (anti prompt-injection UX).
  • Off-schedule и casebusy визуально отделены; collision panel предлагает firstFittingSlot без каскада.

Находки

IDSevСуть
H5-1 P1 Stepper теоретически позволяет «перепрыгнуть» в Виконано без реального in_progress — риск фейкового дохода CEO / искажения KPI.
H5-2 P2 Touch-targets 5-min grid на desktop ниже WCAG 24–44px (есть media-query boost, но default плотный).
H5-3 P2 Желаемое окно waitlist в прошлом → «вечный» waiting (если ещё не закрыто сервером).
H5-4 P3 Некорректные часы графика «18:00–08:00» могут дать пустую сетку без объяснения «график невалиден».
H5-5 P2 Смена modality кабинета в Setup без warn о существующих записях.
Рекомендации: stepper только sequential + server guard; min date на waitlist window; validate schedule UI before save; confirm modality change.

6 Recognition rather than recall 7/10

Показывать, не заставлять помнить.

Что сделано хорошо

  • Легенда слотов (вільно / tight / busy / buffer / break / offsched).
  • Бейджи origin, studies_changed_by, contraindications.
  • StatsBar как фильтры-состояния (recognition очереди).
  • Placeholders и miss-labels при валидации Booking.
  • Busy chips «13:25–14:35 +5 хв».

Находки

IDSevСуть
H6-1 P1 Горячие клавиши (n / r 1–9) нигде не показаны в UI (только placeholder «( / )» у поиска). Power-feature не discoverable.
H6-2 P2 Меню ⋯ скрывает вторичные действия; новичок не знает, что там «організувати кейс».
H6-3 P2 Много состояний очереди (scheduled/waiting/in_progress/done/no_show/not_held/cancelled/needs_reschedule + derived late/clarify) — без legend/хелпа на доске.
H6-4 P3 Density control в sidebar без превью «как изменится доска» до выбора.
H6-5 P2 В call-list иконки ☎ ✓ ☏ ↩ требуют memory mapping (есть title, нет visible labels у mini-icon).
Рекомендации: footer/cheatsheet «Клавіші»; tooltip panel «Статуси черги»; labels на call actions в expanded; progressive disclosure с подсказкой «Ще N дій».

7 Flexibility and efficiency of use 8/10

Ускорители для экспертов, простота для новичков.

Что сделано хорошо

  • Hotkeys регистратуры (раскладка-независимо через e.code).
  • Density compact / comfortable / spacious.
  • Bulk: «Всіх підтверджено (N)», multi-select services/import.
  • Collision one-click move; waitlist candidates после free slot.
  • Phone search normalization; MiniCalendar jump.
  • Referral multi-clinic switcher + aggregate.

Находки

IDSevСуть
H7-1 P2 Нет сохранённых фильтров / «мой кабинет по умолчанию» (кроме local density).
H7-2 P2 BookingModal — большой «god form»; нет wizard-stepper для новичка (всё на одном экране 2 col).
H7-3 P3 Нет keyboard-nav по строкам очереди (j/k или arrows) — только click expand.
H7-4 P2 Radiologist board на узком экране прячет queue (display:none @820px) — tablet у аппарата теряет список.
H7-5 P3 CEO export — ок; нет drill-down «клик по KPI → список записей».
Рекомендации: remember last room/date per user; tablet layout для radio; optional simple booking mode (patient → study → slot).

8 Aesthetic and minimalist design 6.5/10

Только релевантное; не конкурировать за внимание.

Что сделано хорошо

  • Чистая Apple-like dark UI, tabular nums, спокойная палитра.
  • Compact density для «стены из строк».
  • prefers-reduced-motion.
  • Контраст AA для muted/faint (явно правили).

Находки

IDSevСуть
H8-1 P1 Expanded QueueRow — information overload: patient fields, studies, call, priority, stepper, 6–10 buttons, collision panel, case. Decision place хороший, но visual hierarchy слабая.
H8-2 P2 Sidebar: кабинеты + actions + density + user — длинный scroll на маленьком ноутбуке.
H8-3 P2 Booking: одновременно calendar + full 5-min grid + legend + busy chips + case bar — модалка «тяжёлая».
H8-4 P3 Дублирование статуса: badge + stepper + call glyph + late/clarify badges.
H8-5 P3 Inline style={{…}} в компонентах размывает системность spacing.
Рекомендации: в expanded — primary actions strip (1–3) + secondary «Ще»; progressive sections (Пацієнт / Дослідження / Дії); уменьшить chrome в Booking (legend collapse).

9 Help users recognize, diagnose, and recover from errors 7.5/10

Понятный язык ошибки + что делать дальше.

Что сделано хорошо

  • Mapped messages: stale, duplicate waitlist, past, off_schedule, room busy, CASE_*, forbidden priority.
  • dlg-err role="alert" в модалках.
  • Empty states с next step: «Натисніть Новий запис» / «Змініть фільтр» / retry button.
  • Login: не раскрывает enumeration; общее «Невірний логін/email або пароль».
  • Slot taken mid-flight: конкретный слот + clear CTA.

Находки

IDSevСуть
H9-1 P1 Часть ошибок — "Помилка: " + res.error (сырой текст/EN/SQL-ish) без recovery CTA («Оновити», «Обрати інший слот»).
H9-2 P2 Network blip: try/catch есть, но UX = тихий fail или generic; нет offline banner.
H9-3 P2 Import AI: low confidence → unrecognized — хорошо; batch unique fail «все или ничего» без подсветки какой дубликат (known Low L3).
H9-4 P3 404 есть; нет illustrated empty для «немає доступу до кабінетів» у radio.
Рекомендации: error catalog { code → title, body, action }; всегда secondary button recovery; offline strip; import conflict row highlight.

10 Help and documentation 5.5/10

Справка должна быть под рукой, когда нужна. — слабейшая эвристика.

Что сделано хорошо

  • HelpTip «?» (CITO, auto-unblock, referral policy) — правильный паттерн.
  • Placeholder hints; title на disabled.
  • PRODUCT_OVERVIEW / handover — для dev, не для end-user.

Находки

IDSevСуть
H10-1 P1 HelpTip почти нигде: нет на collision, delay plan, cases, waitlist window, priority, buffer, off-schedule.
H10-2 P1 Нет first-run / empty clinic checklist (кроме ctx-hint «додайте обладнання»).
H10-3 P2 Нет in-app «Довідка» / PDF для регистратора; пароль-reset по email отложен — support friction.
H10-4 P2 Hotkeys undocumented in UI.
H10-5 P3 Setup Wizard: много power без guided «що далі після configure».
Рекомендации: HelpTip на 8–10 critical concepts; page «Швидкий старт» 1 экран; keyboard overlay ?; link «Підтримка» в sidebar.

Сквозные темы

Не привязаны к одной эвристике — влияют на весь продукт.

Accessibility (WCAG) 7/10
focus-visible, modal a11y, contrast, reduced-motion — strong; toast live regions, touch slots, some icon-only — weak.
Multi-role IA 7/10
Портал и radio отдельны; sidebar/role still leaky.
Mobile / tablet 5.5/10
Desktop-first; radio @820px ломает workflow у аппарата.
Cognitive load 6/10
Доска = cockpit; нужна иерархия actions в expanded row.
Trust & safety UX 9/10
Fail-closed на слотах/инцидентах — образцово для SaaS-очереди.

Топ приоритетов — что чинить сначала

P0 / P1 Высокий impact, умеренный effort

  1. Единый Toast + aria-live + semantic colors + longer errors.
  2. Закрыть hotkeys под всеми модалками (emergencyOpen, case, delay, confirm, wlSuggest…).
  3. Stepper / done: только валидный path; server reject skip.
  4. Radiologist archive readOnly согласовать с UI-копирайтом.
  5. Role-aware Sidebar (не показывать dead actions).
  6. Discoverability hotkeys + 3–4 HelpTip на collision / buffer / case / waitlist.

P2 Следующий спринт UX-полиша

  1. Visual hierarchy expanded row (primary / secondary actions).
  2. Touch targets slot grid ≥ 32–40px (или long-press + larger mode).
  3. Dirty-guard на Booking / Reschedule.
  4. Soft-undo / clearer recovery CTA на error toasts.
  5. Tablet layout для радиолога.
  6. Waitlist past-window prevention.

P3 Backlog polish

  1. Глоссарий терминов / меньше emoji noise.
  2. CEO drill-down.
  3. Keyboard row navigation.
  4. First-run checklist.

Что хвалить (не ломать)

Fail-closed занятость / простои / ошибка загрузки — редкий уровень зрелости для SaaS-очереди.
Decision panels (запізнення, накладення, off-schedule confirm) — UX «на месте решения», не в отдельном wizard.
Единый SlotPicker + легенда busy/buffer — объясняет физику кабинета.
Modal a11y (useModalA11y) и density control — осознанный craft.
Confirm copy с объяснением последствий (declined = cancel) — зрелый error prevention.

Итог

RadFlow — операционный cockpit, а не маркетинговый UI. По Нильсену он особенно силён в #5 Error prevention и #1 Status (данные/realtime), слабее в #10 Help, #8 Minimalism (перегруз строки) и #4 Consistency (тосты, archive-mode, nav по ролям).

Если брать один фокус на ближайшую итерацию: «Feedback + Control under stress» — единые accessible toasts, no hotkeys under critical modals, честный read-only/disabled, короткая primary-action полоса в карточке пациента.

Общая оценка UX: 7.5 / 10. Продукт готов к ежедневной работе регистратуры; UX-долг не блокирует релиз, но ограничивает скорость обучения новых сотрудников и устойчивость на tablet.
