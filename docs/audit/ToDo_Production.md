### Подробности П-3 (чтобы не исследовать заново)

1. Google Cloud Console → проект RadFlow → Google Auth Platform (бывший «OAuth
   consent screen») → **Audience** → `Publish app`.
2. ⚠️ **После переключения переподключить ОБА центра.** Токены, выданные в
   `Testing`, свой 7-суточный срок сохраняют; новый срок получают только новые
   токены. `buildAuthUrl` идёт с `access_type=offline` + `prompt=consent`,
   поэтому переподключение гарантированно выдаёт новый refresh-токен.
3. **Верификация.** Наши scope (`calendar.events`,
   `calendar.calendarlist.readonly`) у Google — sensitive. Без верификации
   приложение в проде работает, но показывает экран «Google hasn't verified
   this app» и имеет лимит на число аккаунтов. Верификация требует
   верифицированного домена (П-2), политики конфиденциальности на том же
   домене, демо-видео и обоснования каждого scope.
4. ⚠️ **Критерий приёмки — ЗАМЕР, а не вера.** Через 8 дней после
   переподключения: `select * from public.important_events where event_type
   ilike '%gcal%'` — если `reauth_required` не появился, статус сработал.
   Инструмент уже есть: проверка №13 после 0194 краснеет с меткой
   `відвалилось(...)`.
