# PR — с79: права панель на ≤1240 px другим рядком (Н-11), відступи шапки (Н-12), «☰» на телефоні (Н-13)

Дата: 24–25.09.2026. Гілка `s79-rpanel-tablet` (`f11deeb` → `32e07fd` → `8e40bdd`; на машині
власника після `git am` — `769b6ff` → `77bac5a` → `3444834`) → `dev` → `main 386aed6`
(merge `--no-ff`). Міграцій немає. Лише CSS (`styles/prototype/radflow.css`) і сторож
`tests/tabletPanel.test.ts`.

## 1. Що було

* **Н-11.** `@media (max-width: 1240px) { … .rpanel { display: none; } }` стояло в
  `radflow.css` РАНІШЕ за базове `.rpanel { … display: flex … }` тієї самої специфічності й
  програвало. На планшеті панель черги (міні-календар, «Потребують перенесення»,
  «Зачеплені інцидентом», обдзвін, скасовані з відміною) малювалась смугою під списком.
* **Н-12.** У правилі `.topbar` `padding-top/bottom: 4px` перебивав пізніший `padding: 0 22px`;
  у компактній щільності верх кільця фокуса «＋ Новий запис» був за краєм екрана (y ≈ −3,7).

## 2. Рішення власника (24.09)

Панель НЕ ховати, а зробити нормальним другим рядком під списком — усі функції лишаються на
планшеті біля апарата. Н-12 — тією самою правкою CSS.

## 3. Що зроблено

* ≤1240 px: `.content-wrap { grid-template-columns: minmax(0,1fr); grid-template-rows: 1fr
  fit-content(40%) }`; `.rpanel { display: grid; grid-template-columns: repeat(auto-fill,
  minmax(min(100%, 15rem), 1fr)); align-items: start; max-height: 40dvh; border-top … }`.
  Список бере щонайменше 60 % області, панель — не більше 40 %; легка панель радіолога — за
  вмістом. `1fr` (а не `minmax(0,1fr)`) — щоб на дуже низькому вікні панель не лягала на список
  (знахідка ревʼю р1). `max-height: 40dvh` — страховка для WebKit, якщо відсоток у
  `fit-content()` там не розвʼяжеться (у Chromium не змінює нічого — 840/840 випадків).
* Шапка: `.topbar { padding: 4px 22px }`, щільності задають лише горизонталь.
* **Н-13 (попутно):** на ≤480 px «☰» перекривав іконку/заголовок шапки в compact/spacious
  (правила щільності (0,2,1) били мобільне `padding-left: 3.5rem`). Резерв під «☰» тепер лише в
  рядку заголовка: `.topbar > .tb-title { padding-left: 2.75rem; min-height: 2.75rem }`.
* `scroll-padding-block: 6px` на `.rpanel`, `.content`, `.content-full`, `.sb-nav`,
  `.content-wrap` — кільце фокуса не ріжеться краєм прокрутки (зрізаних кілець 2368 → 74 на
  45 696 зупинках Tab).
* Імена пацієнтів і назви кабінетів у картках панелі на ≤1240 px переносяться замість три
  крапки (обрізаних 1879 → 0).

## 5. Ревʼю

* **Раунд 1 (каскад і розкладка на всіх екранах):** перекриття списку панеллю на дуже низькому
  вікні (Medium, закрито `1fr`); дірки в тесті (переписано — модель каскаду з вирізанням
  коментарів, розгортанням shorthand, контекстами з брейкпоінтів); +7 px `/ceo`; «☰» на ≤480
  (Н-13); залежність від WebKit (`40dvh`).
* **Раунд 2 (доступність, фокус, сенсор):** Н-11 чистий (Tab, дерево доступності, сенсор, 2D-
  прокрутка); перша редакція Н-13 надто дорога на 200 % — замінено резервом у рядку заголовка;
  тест пропускав вкладений CSS, `transform`/відʼємні `margin`, ширину «☰», обгортку `aside` у
  TSX — закрито (форма оболонки звіряється через AST TypeScript); `scroll-padding-block`;
  перенесення імен.
* Мутації: 90 на копії, усі — очікуваний результат.

## 6. Межі (не регрес с79)

* Замір лише в Chromium; iPad/WebKit — ні (є страховка `40dvh`).
* 481–800 px: права група шапки не переноситься («＋ Новий запис» частково за краєм при
  великому шрифті); ≤480 px при 200 % частина шапки за правим краєм.
* На горизонтальних планшетах міні-календар влазить у смугу панелі на 81–95 % (кнопка
  «✎ Графік» — після прокрутки панелі); у радіолога одна картка займає третину ширини.
* `.room-cards` на ≤980 px ширші за колонку; два безіменні `complementary`, немає орієнтира
  `main`, у `rcard-toggle` немає `aria-expanded`.
* Перенесення імен тримається на інлайновому `textOverflow` у TSX (пін червоніє, якщо його
  змінити).
